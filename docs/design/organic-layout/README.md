# Organic 版面重做 —— 018 的规格参照

017 换的是**主题**（令牌、药丸、圆角、字体）。这一包换的是**版面**：留白节奏、
内容列宽度、字号层级、地面分工、数量图形的形状。开发者的原话是
「你实际上只修改了主题而不是页面布局」—— 这份交接包是对那句话的回应。

| 文件 | 是什么 |
|---|---|
| `handoff.md` | **规范正文。冲突时以它为准**（它自己这么写的）。令牌表、八条全局规则、间距字号表、九屏逐屏尺寸 |
| `Principles.dc.html` | 八条全局规则的图示 |
| `Review.dc.html` | 七条审视结论的完整版 —— 为什么要重做 |
| 其余七个 `.dc.html` | 逐屏参考稿。**只看 `<x-dc>` 与 `</x-dc>` 之间**，其余是预览外壳 |

**参考稿是设计稿，不是生产代码。** 它们用内联样式写成，只为把意图表达到像素级。
实现必须用仓库已有的组件（`Table`、`Field`/`FieldGroup`、`Dialog`、`Badge`、`Button`）
与 Tailwind 工具类重建，不是把内联样式搬过来。

## 三处必须知道的前提偏差

这份稿子的**令牌表是 017 之后的**（`--ring: #8c491a`、`--accent-2`、
`--chart-1: var(--accent-2)` 都是 017 新建的），但它的**页面事实是 017 之前的** ——
设计 agent 的令牌来自同步上去的设计系统，页面结构来自 GitHub 上的 main，
而 017 的提交当时还没推。所以：

1. **它说 `AppShell` 是 `mx-auto max-w-7xl` + 顶部横向导航** —— 017 已经改成左侧栏。
   它对居中列的批评仍然成立（内容列还没贴左、还没有 960px 上限），但「横向导航」已过时。
2. **它说仓库有完整 `.dark` 分支与一键切换，需要产品决定** —— 017 已整套拆除。
   这条（审视第 4 条、文末「待你决定的一件事」）**已经解决，不在 018 范围内**。
3. **它的实现点提到 `features/overview/CategoryChart.tsx`** —— 017 已删除，
   recharts 一并拆掉，取代它的是 `features/overview/DistributionBar.tsx`，
   而且已经是稿子要的药丸轨道形态。

**还有一处它看不见的：** `AssetList.dc.html` 规定六列，没有勾选列、没有批量条、
没有行尾悬浮按钮。那整套是 017 第四阶段做的，源头是开发者自己提的
「批量操作点击次数过多」，有 7 条 DOM 测试守着。**稿子没画它不等于反对它** ——
018 保留全部交互，只按稿子的尺寸重排。

## 与 017 的分工

017 定的这些**不改**：颜色分工（陶土=动作 / 鼠尾草=数量 / 八个状态槽=状态）、
八个状态调色板、只有一套浅色、字体自托管、`index.css` 的令牌值。

018 改的是版面。`handoff.md` 明确写着「**没有引入任何新令牌**，
`web/src/index.css` 不需要改」—— 除了焦点环的实现方式（见下）。

**唯一一处需要重新量的：** 稿子写焦点环是
`outline: 2px solid var(--ring); outline-offset: 2px`；017 做的是 3px 实心
`box-shadow` ring —— 因为 shadcn 默认的半透明环在奶油底上只有 1.69，
而 WCAG 1.4.11 要 3:1。颜色两边一致（都是 `#8c491a`），机制不同。
换成 outline 时**必须重新量对比度**，不能假定换个机制数字还成立。
