# 表格页、列表与页面骨架

改 `web/src` 之前读这一份，以及同目录的 `web-forms.md`。
「列表有两种形状」那条服务端也要遵守，所以 `internal/httpapi` 也指着它。

- **元数据表格：点击行编辑，右键出操作菜单。** 不留成列的操作按钮。
  不适用的菜单项**禁用而不是隐藏**。破坏性操作要 `confirm` 并输入该行标识，
  **待输入的标识要能一键复制**（`ConfirmDialog` 里的 `code` + 复制按钮）——
  手抄一串编号只会抄错，抄错并不会让删除更安全。
  **复制一律走 `lib/clipboard.ts` 的 `copyText`，不要直接调 `navigator.clipboard`** ——
  它只在安全上下文里存在，而这套系统是 `http://内网地址:8080` 跑的，
  那里 `navigator.clipboard` 是 `undefined`，裸调加 try/catch 的结果就是按钮毫无反应。
  降级路径是选中该节点的文本再 `execCommand("copy")`（选中而不是隐藏 textarea，
  因为对话框会抢焦点）；两条路都失败就明说「已选中，按 Ctrl+C」，不要静默。
  约定集中在 `CrudPage` 的 `onRowClick` / `rowActions`，不要在页面里各写一遍。

- **资产表格是手写的**（勾选、分页、动态列），不走 `CrudPage` —— 改这条约定时
  要记得它也要跟上；007 定规范时就漏了它一次。
  **显示列是筛选行右端的三点 `DropdownMenu`**（`DropdownMenuCheckboxItem`），
  不是一整块复选框。**选择按类别分别记忆**（`nexus.assetColumns` 是
  `{类别id: 键[]}`，不再是一个扁平数组），渲染前还要再与当前类别的
  `available` 求交 —— 否则字段被解绑、或类别刚切换 schema 还没到，
  就会画出一列有表头没内容的空列（表头还退化成英文键名）。
  **设备字段的列由型号筛选或厂商筛选解锁**（016 起后者也算）：绑到厂商的字段，
  到达集是该厂商旗下全部型号，只按「筛到某一款型号」判会让它永远选不中 ——
  而筛了厂商之后屏幕上剩下的本来就全是它的设备，正是这条规则说的那个条件。菜单要 `modal={false}` 且 `onSelect` 里 `preventDefault()`：
  勾一列就是为了看它出现，模态菜单会把表格设成 `aria-hidden`（测试也因此找不到表头），
  而每勾一次就关一次会让选四列跑四趟。
  **翻页只有一份实现**：`features/common/Pager.tsx`（区间行、每页条数、页码），
  **一整行**（左区间、中页码、右每页条数），且**放在表格下方**——读完一页才需要它。
  资产表与审计表都用它，不要再抄一份。
  `PaginationPrevious`/`PaginationNext` 的可见文字上游是写死的 "Previous"/"Next"，
  已改成可由 children 覆盖 —— 那两个词是全站唯一没走目录的文案，
  而 `aria-label` 是我们自己传的，所以按名字找元素的测试一直是绿的。
  **筛选是一栏**：控件横排一行，标签 `sr-only`，「全部 X」写在控件自己的值里，
  不要在控件上方再堆一层文字。
  **筛选与翻页都写进地址栏**（`setSearchParams(..., { replace: true })`）——
  否则点进一台设备再返回，筛选全没了，人要重新缩一遍。用 **replace 不用 push**：
  筛选不是一个「去过的地方」，push 会让「后退」把搜索框的每一次击键都倒一遍，
  而不是回到刚才那台设备。资产、审计、字段三页都照此办理；
  比较的是 `useSearchParams()` 的值，不要读 `window.location`。
  **日期用 `Popover` + `Calendar`**（`mode="range"`），不写 `<input type="date">`；
  语言跟 `getLang()` 走 `react-day-picker/locale` 的 `zhCN`/`enUS`。
  测试里选日期按 `data-day="YYYY-MM-DD"` 定位，别按按钮名 —— 那是整句本地化日期。
  （`DynamicForm` 的 date 字段仍是原生 input，尚未跟上。）
  审计表遵守同一套点击/右键约定，但**审计条目不可编辑也不可删除**（它就是记录），
  所以行点击是**弹 `Dialog` 看前后值**，右键菜单是「查看变更内容」与
  「只看这个对象/类型/操作人」这类收窄筛选。表里**不留「变更内容」这一列** ——
  一列只写「查看变更内容/没有前后值」是噪音，可点与否由光标和禁用的菜单项表达。
  前后值不要就地展开在表格下方 —— 那块内容会落在翻页条以下，用户点了看不见任何反应。
  收窄是看不见的，所以筛出来的条件要以 `Badge` 显示并可一键清除。
  **类别页不再是表格**（024 决策 151，取代 014 对它的适用）——
  见下面「类别页是主从两栏」。其余元数据页不受影响。
  右键菜单在触发时关闭，所以确认框必须渲染在菜单之外（`ConfirmDialog` 有受控模式）。
  **元数据的编辑器一律是 `Dialog`**，不是内联展开的 `Card` —— 那会把整张表推下去。
  **单元格里不放可点击控件** —— 它会连同所在行的点击一起触发，一次点击出两个结果。
  改这一行的任何东西都在编辑对话框里，包括「设为默认库存点」这类一次性动作。
  **对话框里发生的拒绝要显示在对话框里** —— 它背后的页面是 `aria-hidden` 且被遮住的。

- **表格页的零件只有一套**（014 决策 90/92/95）。搜索、筛选、翻页、地址栏同步
  分别是 `features/common/` 的 `ListToolbar`、`useListQuery`、`Pager`；
  六个元数据页由 `CrudPage` 自动获得，资产、审计、类别各有各的手写表格但用同样的零件。
  **不要把手写的三个塞进 `CrudPage`** —— 它会长出「没有新建按钮」「勾选列」「树」
  三个特例开关。筛选值以 API 的键命名（`category_id`、`type`、`status`），
  一份对象同时喂给地址栏和请求；空串 = 不筛，两边都不出现。
  **筛选控件的 id 不能和新建表单里的同名控件撞**（`f-type` vs `f-type-filter`）——
  对话框一开，背后那个变成 `aria-hidden`，`getByLabelText` 就找不到表单里的那个了。

- **列表有两种形状，按问题决定**（014 决策 92）。`/categories`、`/models`、
  `/statuses`、`/holders`、`/users` 带了 `q`/`offset`/`limit` 返回
  `{items,total,offset,limit}`，一个都不带返回**数组**。这是**加**行为不是改行为：
  下拉框要的是全集，分页会把选项截断；而 zenith-printer 的数据源按数组解析
  `/api/categories`，改形状会让对面刷新数据源当场报错。服务端一律走
  `internal/httpapi/listing.go` 的 `respondList` / `matches` / `keep`。
  `/roles` 例外，它从来就是信封（要带 `permissions`）。

- **资产详情是一整页**（022 决策 136，取代 014 决策 89）。
  `/assets/:id` 是**顶层路由**，不是 `assets` 的子路由，`Assets.tsx` 里没有 `<Outlet />`。
  **全部流转就在这一页上**，`/assets/:id/history` 已删除 —— 当初拆出去是因为
  「四十条事件塞进 dialog 是盒子里套一页」，dialog 没了，那条理由也没了。
  **左上角返回恒指 `/assets`**，不是 `history.back()`：扫码、录入完成、审计
  「只看这个对象」进来的人是来读一台设备的，列表才是回答「还有哪些」的地方。
  **列表的筛选串写进详情自己的地址**（`/assets/:id?status=…&q=…`），返回时原样带回。
  从列表点进去要 `navigate({pathname, search: searchParams.toString()})`；
  扫码精确命中**不带**（它本来就不是从筛选里来的）。
  写进地址而不是记在内存里，是因为只有前者能活过刷新与粘贴地址。

- **类别页是主从两栏，不是表格**（024 决策 151–153）。左边一棵**常展开**的类别树，
  右边是选中那一个的完整配置：上级、代号、编号字段、可打印的标签、以及**只读**的字段表。

  **014 把它收进 `CrudPage` 不是写错了。** 那一轮的任务是「表格页的零件只有一套」，
  而类别页当时确实只是一张能搜、能点行的列表。**变的是类别承载的信息**：它现在决定
  一台设备记录哪些字段、能打哪些标签、编号从哪个字段来 —— 而这些**只有开对话框才看得见**。
  于是「这个类别配了什么」每问一次就要开关一次对话框，**而人真正要做的是在几个类别之间来回比**。
  对话框天生做不到：一次只能开一个，且开着时背后那棵树是 `aria-hidden`。

  **不折叠。** 类别是配置不是数据，一屏到几十个，整棵树放得下；一个把「有哪些类别」
  的答案藏起来一半的控件，不值它省下的两行。`CollapsibleTree` 当初就是这么被删的，
  这是同一个想法第二次没能挣回成本。
  **搜索仍然切平展并显示完整路径**（014 决策 91 的理由在这里更成立）；
  **搜索词仍写进地址** —— 以前是 `useListQuery` 顺带做的，换成 `useState` 会静默丢掉它。
  **`/categories/:id` 与 `/categories` 是同一个组件**，不是父子路由：左栏要一直在，
  而把它和右栏拆到路由两端，就得让搜索词、类别列表、选中态跨越路由边界共享 ——
  正是 016 决策 107 警告的形状。未指定类别时 `<Navigate replace>` 到第一个根类别，
  **`replace` 不是 push**，否则后退会退进一个立刻又跳走的地址。

  **右栏只读**：字段的解绑仍在字段编辑对话框里（v6 决策 72），
  改名/移动/编号字段/打印标签仍在 `CategoryEditor` 里一次保存，**删除也留在那儿** ——
  切类别只要点左栏一下，破坏性按钮蹲在一个这么容易换掉的面板上不划算。
  无 `schema.manage` 时**禁用 + 悬停说明**，不隐藏：审计页那条「隐藏而非禁用」的前提是
  「那一页没有任何他可看的东西」，类别页的内容无权限者全都可看。

- **主从骨架只拿形状，不拿内容**（024 决策 156–158）。
  `features/common/MasterDetail.tsx` 管两栏栅格、各自滚动、窄屏塌一栏；
  `useMasterSelection.ts` 管「地址里那个是谁」与「没指定时跳哪」。
  **两者都不知道条目是什么** —— `tests/masterDetail.test.tsx` 是源码不变量，
  断言骨架里不出现「类别 / tree / count」这些词，并断言**只有一个调用方**。

  判据是**它在决定「页面的形状」还是「这一页的内容」**。
  显式没做、且不要顺手补上的三件：**左栏宽度参数**（一个调用方，写死 300px）、
  **空状态插槽**（空态是内容，调用页自己画）、**键盘上下键移动选中**
  （树与列表的键盘语义不同，现在定会定错）。
  第二个调用方进来时最可能要加的是宽度 —— 那是**形状**参数，十行改动，可以加。
  **不要加渲染回调。** `CrudPage` 就是这么长出三个特例开关的，
  回调是伪装成参数的分支，每多一个调用方就多一个。

- **同一个系统只有一种「这类有多少台」**（024 决策 154–155）。
  `GET /categories/counts` 返回每个类别的**子树合计**（含子类别、排除
  `counts_as_available = 0` 的状态），**概览的根类别数字就是这份结果里根类别的那几条** ——
  两处不是「口径一致」，是同一个数字被读了两次，构造上不可能不等。
  **没有设备的类别也返回 0**：树上该有数字的地方留白，读作「没加载出来」，不是「没有」。
  服务端归并用 `schema.AncestorIDs(path)`，它**已包含类别自身** ——
  再 `append` 一次会让每个类别自算两遍，叶子翻倍而根类别看起来还「差不多对」，
  是最难从数字上看出来的那种错。

- **类别页不翻页，一搜索就从树切成平铺**（014 决策 91）。树上放分页会让第 2 页
  开头的子类别失去它在第 1 页的父，缩进就成了没有出处的悬空；搜索同理，
  所以命中行改显示完整路径「网络设备 / SDWAN 路由器」。清空搜索恢复成树。

- **账号能改的东西在行点击弹出的编辑对话框里**（014 决策 93/94）。
  邮箱只读、姓名可改、角色可改（013 的两条守卫不变），
  **停用与启用成对** —— `PATCH /users/:id` 的 `{"disable": false}` 以前被读了
  但被忽略，误停一个同事只能去改数据库。**重置密码仅本地账号**，
  OIDC 账号禁用并说明；破坏性操作走 `ConfirmDialog` 并要求输入该账号邮箱。

- **页面骨架有三个共用件**：`features/common/` 的 `PageHeader`（标题 + 一句说明 +
  右端动作）、`TableFrame`（`overflow-x-auto rounded-md border`）、
  以及 014 的 `ListToolbar` / `useListQuery` / `Pager`。**页面容器一律 `grid gap-6`**，
  不要再各写各的 `ml-auto` 与 `gap-5`。卡片用全套组合：标题下的那句话是
  `CardDescription`，右上角的控件是 `CardAction`，都不要用 `<p>` 或 `ml-auto` 手搭；
  表单容器是 `FieldGroup`（栅格写成 `className="sm:grid sm:grid-cols-2"`），
  空状态是 `Empty`，提示是 `Alert`。`Field` 默认占满宽度 ——
  要窄的控件把宽度写在 `Field` 上，写在 `SelectTrigger` 上不生效。

- **候选多的下拉可搜，候选少的不必**（023 决策 149）。厂商、型号、持有方/负责人、
  类别用 `SearchSelect`（Popover + Command）；状态、角色、动作类型继续用 `Select`。
  判据是候选集会不会无界增长 —— 一个只有五项的下拉配一个搜索框，
  是在五个选项前面摆一道门。匹配为**包含、不分大小写、不要求从头**：
  人是照着标签念出中间几个字符的。
  **不要试图在 `Select` 里塞输入框** —— Radix `Select` 内建按首字母跳转的 typeahead，
  会和输入框抢每一次按键。这正是 shadcn 另起 `Command` 做 Combobox 的原因。
  `SearchOption.keywords` 让搜索能匹配到不显示的文字（类别的完整路径、型号的厂商），
  行仍以名字打头。

- **审计是两栏两条路由**（023 决策 145）：`/audit`（操作审计）与
  `/audit/transfers`（流转审计），走 `MetadataTabs`。理由与型号/厂商同一条：
  两个都写地址栏的列表挤在一个地址下会互相踩（016 决策 107）。
  **没权限的页签隐藏而非禁用** —— 与审计入口既有的例外一致；
  只剩一个页签时整条栏不画，一个没有选择的选择器是噪音。
  **流转不写审计流水**，两栏来自不同的表，不要试图合并。

## 版面数字（018）

**这些数字不是风格偏好，是量出来的，改之前先读完这一节。**

| | | 为什么 |
|---|---|---|
| 表格行高 | **48px** | 来自 `TableCell` 的 `py-[14px]` + 20px 行盒，**不是** `TableRow` 上的 `h-12` |
| 单元格内边距 | `px-5 py-[14px]` | 表头同款；表头字重 600、色 `--secondary-foreground` |
| 分区之间 | **56px**（`gap-14`） | 页标题与内容之间也是这个 |
| 区内成组 | **22px**（`gap-[22px]`） | 搜索条 / 表格 / 翻页条是**一组**，不是三个分区 |
| 内容列 | **等于面板宽度，没有任何宽度规则** | `AppShell` 一处设定，见下 |
| 圆角 | **32 / 28 / 20 / 999** 四档 | 对话框面板 / 容器 / 下沉块与提示块 / 小控件。**32 只给对话框**，见 `index.css` 注释；另有例外两处 |
| 输入与选择 | **48px**（登录 50px） | 按钮**不按高度规定**，按 `py-3`（≈44px） |

### 内容列：**没有**宽度规则（决策 135）

`AppShell` 里内容列那个 `div` 上**一个宽度类都没有** —— 块级元素本来就等于容器宽度。
内容与屏幕右缘之间只剩面板自己的 `pr-10` 加井槽 `p-3`，**恒为 52px**。

这条问题问了三遍，这是第一个不含数字的答案：

| | 规则 | 2560 下右边留白 |
|---|---|---|
| 018 | 固定 `max-w-[960px]` | 1244px，且随窗口无界生长（1440 下 14% → 3840 下 73%） |
| 020 | `w-[min(100%,max(960px,76%))]` | 581px，占比锁死在 24% ——**增长治住了，留白没治** |
| **135** | **无** | **0**（右缘距屏幕恒 52px） |

020 修对了「留白随窗口长大」，但没修「留白本身」：2560 上那 581px 空白让页面读起来
像是没加载完，而不是像被排版过。所以留白连同不对称一起去掉了。

**右内边距是 `pr-10`（40px），不是井槽的 12px。** 理由是**左右差**，不是圆角 ——
实测右上角按钮距面板顶 46px，圆角方框只占顶部 28px，两种内边距下它都进不到弧线区域。
真正的问题是 56 : 12 读作没对齐，而 56 : 40 读作有意收边；而且贴那么近本身就局促。

**已接受的代价**（看过 2560 截图后定的）：宽表格的列会被拉开而不是提前结束；
**960 地板没了**，≤1548 的窗口不再与 018 逐像素一致（1440 下内容列是 1084）。

**不要给某一页单独设宽度**，也不要给内容列加回任何宽度类。
018 有过三档（960 / 760 / 620–640），020 拆掉逐页的，135 拆掉最后一条。
判据没变：**它在决定「这一页多宽」还是「这个部件自己多宽」** ——
前者现在一处都没有，后者（搜索框的 640、备注列的 `max-w-48`）留在原地。
`tests/contentColumn.test.ts` 守着这条：`routes/`、`features/` 下的 `max-w-`
命中集合必须等于白名单。**AppShell 里已经没有数字可以跟它抵消了**，
所以一个漏进来的 `max-w-` 会直接生效 —— 这条测试现在是唯一的拦截。

实测脚本 `specs/020-fluid-content-column/measure.mjs` 量八档窗口 ——
桌面六档（3840/2560/1920/1440/1366/1280）要求留白为 0、右缘恒 52px，
移动两档（700/390）要求留白同样为 0、右缘 20px（`md` 以下面板换成 `p-5`、井槽为 0）。
**分档的是常数，不是规则。** 把任何宽度规则贴回去它都会报错（已双向验证）。

### 带控件的单元格必须 `py-0`

`TableCell` 里已经写了 `[&:has(button)]:py-0`、`[&:has([data-slot=badge])]:py-0`。
**不要拿掉。** 一个 22px 的状态芯片或 32px 的行尾按钮组，加上 28px 内边距，
会让有芯片的行比没芯片的行高一截 —— 一列里两种行高。

参照稿不会遇到这件事，因为**它的芯片是普通 inline `<span>`**，
而行内盒的纵向内边距根本不进入行盒。我们的 `Badge` 是 `inline-flex`，
是一个原子行内块，它的高度会顶进行盒里。这是这一轮花时间最长的一处，记在这里。

### 中文标题不要挂 `font-heading`

Caprasimo **只有 latin 子集**。挂在「资产」两个字上，什么也不会发生 ——
017 曾经为它「没有粗体」写过一整段推理，而前提是错的：那两个字从来没被它渲染过。

中文层级靠字号字重：页标题 `text-[40px]/1.2 font-bold`，区标题 `text-[21px] font-bold`。
`PageHeader` 的 `title` 收 `ReactNode`，所以标题本身是拉丁的页面自己传进来。

**`font-heading` 分的是标题与单元格，不是数字与文字。**
拉丁标题该挂：资产详情页的 `<h1>` 就是设备编号，Caprasimo 能渲染它的每一个字形，
那是全站唯一一个本身是拉丁的页标题；统计数字、页码、流程序号同理，读一眼的量。

**但同一个编号出现在表格单元格里就用普通字体** —— 那里它不是页面的名字，
而是一个要对着实物标签逐字符比对的值，显示体只会让比对更慢。
列表页、概览的最近流转、流转审计的资产列都属于这一类。**`tabular-nums` 两种情形都要**，
同列的数字得对齐。

> 未决：资产列表的粘性编号列至今是 `font-mono`，是全站唯一的第三种写法。
> 要么并进这条规则，要么写下它为什么该不同 —— 别再让它这么悬着。

### 焦点环是 outline，不是 ring

`index.css` 的 `:focus-visible` 一条管全站：`outline: 2px solid var(--ring); outline-offset: 2px`。
**不要在组件上再写 `focus-visible:ring-*`，更不要写 `outline-none`** ——
后者会把全局规则关掉，而它偏偏出现在最需要焦点环的那些控件上。

唯一的例外是 `InputGroup`：环画在药丸本身，内层 `input` 用 `focus-visible:outline-none` 让位，
否则 outline 会在圆角组里横着画一个矩形。

四种底色实测 5.09–6.22:1（WCAG 1.4.11 要 3:1）。017 那版失败在**半透明**（1.69），
不在机制 —— 换机制时重量过一遍，数字记在 `specs/018-organic-layout/research.md` 第五节。

### 表格框：卡片色、翻页条在框内、两头粘住

**表格框坐 `--well`**（与导入步骤卡、详情属性块、打印作业卡同一档），
**表头不再自带底色** —— 框已经是 `--well`，再刷一层等于把同一个颜色刷两遍；
分隔列标题与第一行的是它下面那条整强度的线。

**翻页条进 `TableFrame` 的 `footer`**，不是放在框下面。两个理由：
它属于它所翻的那张表；而放在框下面时，**它是浮起的批量条第一个盖住的东西**。
`footer` 在框内但在横向滚动之外 —— 跟着列一起横滚的翻页条，是需要去找的翻页条。

**列过多时两头都要粘住。** 实测：不粘的话，勾选框与操作列**永远不可能同时可见** ——
它们在一张比框还宽的表的两端，滚过去看见一个就丢掉另一个，而右滚还会连资产编号一起带走，
「我在操作哪一台」都答不上来。所以资产页粘三列：勾选框、编号（左），操作列（右）。

**粘住的格必须自带不透明底，且要覆盖行的每一种状态。** 漏一种，滚过去的字就从它底下透出来。
这个产品只有两种要覆盖（平时 `bg-well`、悬停 `group-hover/row:bg-accent`）——
因为**选中行没有自己的底色**：`TableRow` 里那条 `data-[state=selected]` 是 shadcn 的约定类，
本产品从未给行设过那个属性，行上的 `data-state` 是 Radix 右键菜单写的 `closed`/`open`。

**粘住的格有层级，浮起的东西要压过它们。** `ActionBar` 因此带 `z-20` ——
没有它时，粘住的列会把「浮在表格之上」的批量条盖掉一半。

**`Table` 自带横向滚动容器，`TableFrame` 不要再加一层。** 加了之后外层永远不滚、内层干所有活，
而 `position: sticky` 认的是最近的滚动祖先 —— 两层滚动容器会让人调不明白粘住为什么不生效。

### 底栏与批量条（020 后）

**底栏读作两块**：左边一句「有多少」，右边一整块「能对它做什么」——
翻页与每页改的是同一件事（这一页显示什么），挨在一起，不拆到两端。

**文案显示短、读出长。** 区间显示 `1–10 / 60`，`aria-label` 是完整的
「第 1–10 条，共 60 条」—— 前者够当摆设，后者念出来才是一句话。
`每页` 这个标签是 `sr-only`：值本身已经写着「10 / 页」，前面再加一个标题是说两遍。

**翻页按钮不得小于 24×24。** WCAG 2.5.8 的目标尺寸下限就是 24 —— 缩小底栏时到此为止。

**批量条是深色药丸，不是卡片。** 它要在四十行滚动的表格上被一眼找到，
而这套配色的四档地面彼此只差 1.00–1.22:1，没有一档扛得起这件事；`--foreground` 扛得起。
**它只放四个动作**：流转、导出、删除、打印标签。五个流转动词曾经都在这里，
那是把菜单摊在条上写了一遍 —— 它打开的对话框本来就会再问一次。

**这条上的删除按钮不用 `--destructive`，这不是疏漏。**（022 决策 141）
它的底是 `--foreground`。黏土色在上面只有 **2.53:1**，它取代的那个红是 3.48 ——
两个都不到 4.5，也就是说换色只会让一个本来就不达标的地方更不达标。
设计稿只覆盖浅色背景，这条药丸是产品里唯一的深色表面，稿子从没画过它。
所以它跟着这条药丸自己的反色规则走（浅字 + 半透描边，**15.17:1**），
危险性交给垃圾桶图标与文案 —— 意思本来就在那儿。
**全站唯一一处破坏性动作不用破坏性颜色的地方。看着像忘了改，是量出来的。**

**有选择时不弹行右键菜单。** 一次右键没法同时表示「这一台」和「已选的 N 台」，
而批量条就在下面、给的正是同样的动词。
