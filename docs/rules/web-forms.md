# 表单、文案与前端资源

改 `web/src` 之前读这一份，以及同目录的 `web-tables.md`。

- **`cn` 从 `cn` 包导入，不是 `@/lib/utils`。** 那个文件已删，`clsx` 与
  `tailwind-merge` 也从直接依赖里移除了（`cn` 是这两者的编译版替代，API 相同）。
  shadcn CLI 从 4.21 起给新组件写的就是 `import { cn } from "cn"`，两边一致，
  不会每 add 一个组件就漂一次。**别再建第二套类名合并实现** ——
  两套并存的差异，只会在某个覆盖忽然不生效的时候才被发现。

- **提示文案：简洁；有输入框的进输入框，没有的进问号。**
  一句提示只写「此刻要做什么」，不写规则为什么存在 —— 那些留在代码注释里。
  **有输入框的（`Input`/`Textarea`）写进 `placeholder`**，不要在下面另起一行；
  它在需要的那一刻被读到，且不占版面。**没有输入框的**（`Select`、`Checkbox`、
  `ToggleGroup`、一组勾选项……）挂到标签右边的问号上 ——
  `features/common/Hint.tsx`，shadcn 的 `HoverCard`，鼠标悬停或键盘聚焦才展开。
  **不要再往控件下面堆 `FieldDescription`**：一屏说明比控件还多的时候，
  没有人会读其中任何一条。
  **三类东西不适用**，它们必须一直可见：**拒绝**（`FieldError`）、
  **勾之前就该知道的后果**（`Alert`，例如「这会波及 N 台设备」）、
  以及**当前状态的说明**（例如「已经绑定之后不能再换」）——
  藏进悬停里等于没说。

- - **下载一律走 `lib/api.ts` 的 `download()`，不要写 `<a href download>`。**
  凭证只在请求头里，而 `<a download>` 是一次导航，什么头都不带 —— 服务端回 401，
  浏览器只说「无法从网站上提取文件」，页面上一个字都没有。`download()` 带上令牌、
  过期时续期一次再重放、按 `Content-Disposition` 取文件名，拒绝按错误信封抛
  `ApiError` 由调用方就地显示。导出与导入模板都走它。
  **上传也走客户端**（`api.upload(path, FormData)`）—— 导入曾经自己开一个 fetch，
  于是它是全站唯一不会续期的请求，而导入正是「选完文件再回来」的长流程。

- **新建字段与编辑字段是同一个表单**（`features/fields/FieldForm.tsx`）。
  两边曾经各写一份，于是它们各自长出了对方没有的东西：新建能一次勾好几个类别、
  编辑只能一个一个加；新建后来才补上绑型号；数字字段的上下限只有编辑里有。
  **再给字段加输入项就改这一个组件**，`mode="create" | "edit"` 决定哪些冻结。
  **绑定的语义两边不同且必须不同**：新建时勾选只是意向，随创建请求一起提交；
  编辑时字段已经存在，勾一下就是一次绑定请求，取消勾选要先确认（那会让每台设备
  少一个值），这是两个 dialog 之间唯一剩下的差别。

- **重的库要 `lazy` 到自己的 chunk 里** —— 但先问它该不该在。017 把 `recharts`
  整个拆了：那 354KB 画的是一列横条、没有值得读的坐标轴，也就是一条轨道加一段填充，
  CSS 把比例说得一样准（`features/overview/DistributionBar.tsx`）。
  全站 JS 从 1223KB 降到 883KB。**再要画真正的图表（多序列、坐标轴）才把它请回来。**
  `components/ui/chart.tsx` 也随之删了，要用时 `shadcn add chart` 取回。
  测试环境的 `ResizeObserver` 桩留着 —— Radix 的浮层定位靠它，没有它
  `Select`、`Popover`、`DropdownMenu` 在 jsdom 里都找不到。

## 视觉（017 Organic）

- **只有一套浅色。** 深色在 017 下架：没有 `.dark`、没有 `dark:` 工具类、
  没有 `next-themes`、导航里没有切换、设置里没有主题项。
  服务端的 `users.theme` 字段**保留着**（没写迁移），但前端一行都不读。
  **别再往组件里加 `dark:`** —— 它不会有对应的样式，只会是一句永远不生效的类名。

- **圆角两档，互不派生。** `--radius-sm/md/lg` 固定为 8/16/28px（Organic 自己的三档），
  **不再由 `--radius` 用 r−4/r−2/r/r+4 算出来** —— 那个比例在 r=10 时合理，
  在 r=28 时四档全挤在 24–32 之间，下拉菜单项会顶着一个卡片的圆角。
  **小控件不在这条标尺上**：按钮、输入框、页签、分段控件是**药丸**，
  在组件里直接写 `rounded-full`。`textarea` 是例外 —— 多行框的 999px 圆角会切掉首尾行的字。

- **药丸控件必须 `whitespace-nowrap`。** 英文比中文长，不加的话窄屏或英文界面下
  药丸里的字会换行，药丸就变成了胶囊。

- **焦点环是实心的，且颜色是 `accent-700` 不是主色。** WCAG 1.4.11 要 3:1：
  陶土橙在页面底上只有 3.03、在卡片底上 2.69（不合格），而 shadcn 默认的
  `ring-ring/50` 半透明环只有 1.6。现在 `--ring: #8c491a`、环不透明，
  在四种底色上都是 5.1–6.2。**别把 `/50` 加回来，也别把环换成 `--primary`。**
  验收要用真键盘走 Tab —— 程序化 `.focus()` 在按钮上不匹配 `:focus-visible`，
  环根本不会画出来，检查会在什么都没有的情况下通过。

- **颜色不许硬编码。** 全站 `src/routes` 与 `src/features` 里六位十六进制色**零命中**，
  收口时会 grep 检查。要新颜色就去 `index.css` 加语义 token。
  **陶土橙 = 动作，八个 `.status-*` = 状态，沙绿（`--accent-2`）= 数量与装饰。**
  别拿状态色去画不是状态的东西 —— 审计的前后值就是因此**没有**用红绿，
  而是靠标签与左侧竖线区分。

- **字体三款自托管，走 `@fontsource`。** 产物里**不得出现任何**指向
  `fonts.googleapis.com` / `fonts.gstatic.com` 的引用：内网取不到，而且失败是静默的。
  中文只取 400 与 700（九个字重是 27MB），`font-synthesis-weight: none` 要求真有粗体。
  `vite.config.ts` 的 `dropWoffFallback` 会在**产物阶段**剥掉 fontsource 的 woff 旧格式回退
  —— 不做的话 Vite 会多发 197 个文件、6MB，全是给跑不了 React 19 的浏览器准备的。
  它必须在 `generateBundle` 做：Tailwind 的插件自己内联 `@import`，
  `transform` 钩子根本看不到那些字体文件（第一次就是这样静默失败还报了成功）。

## 外壳与地面（018）

**三档地面各归各位，判据只有一句：它浮在页面之上吗。**

- `--background`（`#f9f4ed`）是**内容面板**，全站最亮的一块。
- `--well`（`#f5ead8`）是**下沉面**：表头、只读值组、提示块、状态卡，
  **以及整个外壳的地** —— 内容面板浮在它上面。
- `--card`（`#ebddc5`）只给**真正浮起**的东西：对话框、抽屉、资产页底部那条
  `sticky` 批量条。`components/ui/card.tsx` 是这个概念的原语。
- 页面分区**用留白分隔**。分区 56px、区内成组 22–24px。

**「分区用留白」不等于「内容块不能有底」。** 018 拆掉的是 `<Card>`（`--card` 那档
浮起底），不是所有底色。**内容块坐 `--well` + 28px 圆角 + 26/22 内边距**在产品里
已经是既成写法：导入的三张步骤卡、资产详情的属性块、打印对话框的作业卡、
概览的状态卡与那两块并列内容。**新写内容块照这一套，不要再发明第四种。**

判据是「它是一块**并列的、有边界才读得清的**内容吗」：
- **是** → `--well` 块（导入的一步、详情的属性组、概览并列的两块）
- **否，它只是页面的下一段** → 留白（概览的设备状态、最近流转）
- **长列表一律不装进块** —— 卡片的下边缘会掉到屏幕外，那条边就不再是边界，
  而是一道看不到尽头的墙。

**这两档在 019 换过位置。** 原来页面是奶油、`--well` 更亮，结果侧栏成了
全屏最亮的一块，而当前导航项的浅底压在它上面实测 **1.00:1** —— 相对亮度完全相同，
字面意义上看不见。现在内容最亮、外壳退后。

**别指望用地面表达「选中」。** 四档地面两两之间只有 1.00–1.22:1，
调色板里唯一有分离度的是陶土（对各档地面 2.69–3.30:1）。
**选中态必须靠墨色或形状**，换哪一档底色都救不了。

改之前先跑一遍白名单检查（`specs/018-organic-layout/quickstart.md` 第 5 步）：

```sh
grep -rn "bg-card\|<Card" web/src --include='*.tsx'
```

命中集合必须等于 `ActionBar` + `ui/card.tsx` + `ui/dialog.tsx`。**多一处就是判错了一处。**

### 侧栏：为什么没有发丝线，也没有编号

参照稿交付的版本用 1px 右边框把侧栏与主区分开，并给每个导航项配一个编号。
两条都没有采用，开发者 2026-09-08 裁定：

- **发丝线 → 靠地面分隔。** 稿子自己把这条列为第一条待改进
  （「Organic 明确反对 hairline-only geometry」）。留着它，外壳会成为
  整个产品里唯一一处靠一根线分隔两个看起来一样的区域的地方。
  018 的做法是把侧栏做成一块圆角 `--well` 块；**019 两档地面换位之后，
  侧栏与外围留白成了同一个奶油色，再给它描一个圆角块等于框住空气** ——
  所以现在是**内容面板收 28px 圆角浮起来，侧栏直接坐在地上**，一个都不描。
- **编号 01–11 → 图标。** 十一个导航目的地不是十一个步骤，编号会暗示
  一个不存在的顺序；而且审计页对没有权限的人不显示，编号会缺一个号。
  但编号原本还在做另一件事 —— 让当前项**不必靠整条满填**来标记自己。
  那件事由图标接手：**当前项是图标吃 `--accent-foreground` + `--accent` 浅底 + 字重**。

**导航项的当前态不要改回整条满填陶土。** 那是 017 的做法，也是稿子交付的做法，
它在一块 `--well` 上会重得像个按钮而不是一个位置。

### 图标

**图标来自 lucide，`stroke-width: 2.75`**（稿子第 199 行，Organic 的要求）。
这条在 `index.css` 的 `.lucide` 上一次设定，**不要在调用点重复写** ——
lucide 把宽度画成 SVG 的 presentation attribute，任何 CSS 规则都压得过它。

**导航图标的表在 `features/common/navIcons.ts`，不在 `AppShell` 里。**
两个地方读它：侧栏画它，**空状态借它**（`StateBoundary` 按路由取，最长前缀优先，
所以 `/fields/groups` 继承 `/fields`）。加新页面时把图标加进这张表就行，
空状态会自己跟上；表里没有的路由退回 `InboxIcon` —— 少配一个应当看起来朴素，不是坏掉。

**按名字挑图标会挑错。** 每一个都要在 16px + 2.75 描边下真渲染出来看过：
`TextCursorInput` 就是这样被换掉的（那个尺寸下它像个哑铃），
`Laptop` 也是这样被换成 `Boxes` 的（这本台账记的不只是电脑）。

**不给图标的地方**：状态芯片（状态只由八个色槽 + 名字表达，加图标是第三种编码）、
表格单元格（FR-020）、时间线的动作 chip（它降到 `--well` 就是为了压低存在感）、
页标题（侧栏已经回答了「我在哪」）。

### 菜单里能点的东西，不能点时要说出来

`Item`、`CheckboxItem`、`RadioItem`、**`SubTrigger`** 四种都必须带
`data-[disabled]:pointer-events-none data-[disabled]:opacity-50`。

**shadcn 上游的两个 `SubTrigger` 都漏了这一对**（`dropdown-menu.tsx` 与 `context-menu.tsx`），
后果是：给二级菜单入口加 `disabled`，Radix 会正确地不让它展开，
但**它看起来和能用的一模一样** —— 鼠标移过去，子菜单不出来，界面什么也不解释。
这与本产品「不可用的动作禁用并说明缺什么」直接冲突。

`tests/menuDisabled.test.ts` 守着这四种。**它是源码不变量而非渲染断言** ——
产品里目前一个二级菜单都没有，而 jsdom 也算不出 Tailwind 类的透明度。
它同时挡住 `shadcn add` 把上游那一版重新覆盖回来。

### 对话框的宽度由自己决定，不由最宽的孩子决定

`DialogContent` 是 `grid-cols-[minmax(0,1fr)]`，**不是裸 `grid`**。
`auto` 轨道的下限是最宽孩子的 min-content：**有一个缩不下去的孩子，整条轨道就被顶宽**，
所有被拉伸的兄弟跟着走，而 `DialogFooter` 靠负边距顶到面板边缘 ——
于是**只有底栏看得出来**，它会挂在圆角外面。`minmax(0, …)` 把轨道封在现有空间里，
超宽的孩子自己溢出，而不是把面板从大家脚下抽走。

**典型的「缩不下去」是 `ToggleGroup`**：`w-fit` 的容器 + `shrink-0` 的项，
最窄就是所有标签排成一行。流转的五个动作在中文里够宽，
在英文里要 483px 而面板只有 446px —— **是哪种语言决定了 bug 出不出现**。
所以修法不是把对话框调宽（那只是挪动阈值），是**让它换行**：
传 `spacing`（项之间有间隙、各自成药丸）再加 `flex-wrap`。
**接合式的条不能换行** —— 第二行会以本该在条中间的接缝开头。

`tests/dialogTrack.test.ts` 守这两条，**是源码不变量**：
jsdom 不做布局，任何关于「超出多少」的断言都会无论 CSS 怎样都通过。
真实对齐在浏览器里量，中英各一遍，十个对话框底栏对面板都是 ±1px（那 1px 是面板的边框）。
