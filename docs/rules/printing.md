# 打印服务对接

改 `internal/printing` 或任何与打印有关的东西之前读这一份，
以及 `docs/guides/zenith-printer.md`（英文版 `.en.md`，两份要一起改）。

- **对接打印服务：地址在 `ZENITH_PRINTER_SERVICE_URL`，类别上存一个预设 id**（013）。
  **接法与用法写在 `docs/guides/zenith-printer.md`（英文版 `docs/guides/zenith-printer.en.md`，
  两份要一起改），改这块之前先读它。**
  模板、打印机、纸型、标签几何都留在对方那边 —— `NEXUS_PRINT_SERVICE_URL` 不配时，
  界面上不该出现任何与打印有关的东西。**一次打印 = 一个类别**：模板绑在类别上，
  而字段键只在类别子树内唯一，跨类别的一个作业会把两个不同字段塞进同一列名。
  `GET /api/rows` 是给外部消费的表格视图，**列名用字段键**，内建列加 `sys_` 前缀让路
  （字段键是类别自己的词汇，且今天就有一个叫 `sn` 的字段）。
  打印有两个入口：**勾选栏**（打选中的那些）与**行右键菜单**（打这一台，不必先勾）。
  **一个类别可以有多种标签**（编号标签、位置标签……），存成 `print_preset_ids` 列表；
  **打印时选用哪一种**，只有一种时不问。多种而没选，后端拒绝这一批而不是替人猜。
  **出纸前必须确认**：对话框打开时先 `dry_run` 核对（分批、**待打编号**、用哪种标签、
  哪个类别根本不能打），第二次按下才真的花纸；确认后按钮消失，同一个对话框打不出两遍。
  打印服务**不发 CORS 头**，所以作业状态、预设清单与数据源刷新都由 nexus 转发，
  浏览器不能直接问它。**点开标签外链前先刷新对面的数据源**
  （`POST /api/print/refresh-source {category_id}` → 找出 `sourceKind=nexus`
  且类别对得上的表，逐张 `POST {zenith}/api/data-sources/{id}/refresh`）——
  设计器画的是对方那份行拷贝，不刷的话跳过去看到的是上次有人按刷新时的数据。
  绑同一类别的表**全刷**；**一张都没连不是错误**；**列集变了对方回
  `needsConfirmation` 且不刷**，nexus 不带 `confirmColumnChange` 替人点头 ——
  那意味着字段动了，按列名取值的标签可能当场失效。
  对方序号池消耗掉的号段要显示出来 —— 号在它那边，不说就等于两套编号各走各的。
