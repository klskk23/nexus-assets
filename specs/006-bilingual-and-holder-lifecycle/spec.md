# Feature Specification: 中英双语与持有方生命周期

**Feature Branch**: `001-asset-ledger-demo`（沿用主开发分支，未另开分支）

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "支持中英双语。默认跟随系统。持有方也需要编辑删除功能，和之前的设计对齐"

> **语言规范**（章程原则 V）：本规格正文用**中文**。
> 本轮特性本身改变了该原则的适用范围 —— 见 FR-001 与 plan.md 的原则 V 一栏。

> **与既有规格的关系**：本规格**修订**而非取代 001–005。

| 既有需求 | 本规格的处置 |
|----------|--------------|
| 001 原则 V：用户可见文案是**中文**，集中在两处 | **修订** → FR-001：改为「集中在目录里，每条有各语言的译文」 |
| 001 `internal/httpapi/messages.go` 存放服务端文案 | **取代** → FR-004：文案移入 `internal/i18n` 目录 |
| 003 FR-009：持有方不跟着改为可删除 | **取代** → FR-011~FR-015：改为可删除，停用机制移除 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 英文用户看到英文 (Priority: P1)

一位不读中文的同事打开系统。浏览器语言是英文，界面就是英文 —— 他不需要先找到设置项。

**Independent Test**: 把浏览器语言设为英文后打开系统，确认导航、按钮、空状态、错误提示全部是英文。

**Acceptance Scenarios**:

1. **Given** 浏览器语言以 `en` 开头，**When** 打开系统，**Then** 界面为英文
2. **Given** 浏览器语言以 `zh` 开头或是其他任何语言，**When** 打开系统，**Then** 界面为中文
3. **Given** 界面为英文，**When** 触发任何一条服务端拒绝（层级、状态、删除、字段校验），
   **Then** 提示也是英文 —— 半英文半中文比全中文更糟，因为它看起来像功能已经做好了
4. **Given** 界面为英文，**When** 导出 CSV 或下载导入模板，**Then** 表头是英文，
   而模板的**键名行不变** —— 那一行是给机器读的
5. **Given** 界面为英文，**When** 查看任何时间戳，**Then** 按英文习惯格式化

---

### User Story 2 - 手动切换语言 (Priority: P2)

系统语言是中文，但某位同事想用英文。顶栏点一下就切过去，下次打开还是英文。

**Independent Test**: 点击语言按钮，确认整个界面切换；刷新后保持。

**Acceptance Scenarios**:

1. **Given** 顶栏，**Then** 有一个语言按钮，按钮上写的是**将要切换到**的语言
2. **Given** 点击切换，**Then** 界面全部字符串随之改变，包括导航、表格与对话框
3. **Given** 切换过语言，**When** 刷新页面，**Then** 保持所选语言，不再跟随系统
4. **Given** 切换语言，**Then** 已缓存的服务端响应被丢弃 ——
   否则英文页面下会留着中文的错误提示
5. **Given** 切换语言，**Then** `<html lang>` 随之更新（读屏与拼写检查读它）

---

### User Story 3 - 编辑持有方 (Priority: P3)

仓库改名了，或者备注要更新，或者它现在归另一个部门管。管理员在列表里直接改。

**Independent Test**: 编辑一个持有方的名称、备注与上级，确认保存生效。

**Acceptance Scenarios**:

1. **Given** 持有方列表，**Then** 每一行都有编辑入口
2. **Given** 编辑对话框，**Then** 可改名称、备注与上级；**类型不可改**
3. **Given** 一个位置，**When** 把上级改为「无上级」，**Then** 脱离成功
4. **Given** 一个部门，**Then** 上级选项里**没有**「无上级」—— 规则不是建议
5. **Given** 把某个持有方移到它自己的下级之下，**Then** 拒绝

---

### User Story 4 - 删除持有方 (Priority: P4)

建错的仓库应该能删掉，而不是永远躺在列表里标着「已停用」。

**Independent Test**: 删除一个没人用的持有方；再试一个有设备的，确认被拒绝并列出设备。

**Acceptance Scenarios**:

1. **Given** 一个无引用、无下级的持有方，**When** 删除，**Then** 成功
2. **Given** 仍有设备持有或引用它，**When** 删除，**Then** 拒绝并列出前几台与总数
3. **Given** 它下面还有下级，**When** 删除，**Then** 拒绝并给出下级数量 ——
   静默改挂下级等于替人改了组织架构
4. **Given** 它是默认库存点，**When** 删除，**Then** 拒绝，提示先转移默认库存点
5. **Given** 它只在流转历史里出现过，**When** 删除，**Then** 成功；
   确认框事先说明它在多少条记录里出现过
6. **Given** 上述删除之后，**When** 查看时间线，**Then** 相关记录显示原始 id，记录完整保留
7. **Given** 删除确认框，**When** 未输入该持有方的名称，**Then** 确认按钮不可用
8. **Given** 任何持有方，**Then** 界面上不再有「停用」

## Requirements *(mandatory)*

### 双语

- **FR-001**: 用户可见文案 MUST 集中在目录中，每条 MUST 在每种支持的语言里都有译文。
  「文案是中文」这条规则 MUST 收窄为「文案不写在组件与领域代码里」。
- **FR-002**: 默认语言 MUST 跟随系统；`en` 开头判为英文，其余判为中文。
- **FR-003**: 手动选择 MUST 优先于系统，并 MUST 跨会话保留。
- **FR-004**: 服务端返回的用户可见文本 MUST 按 `Accept-Language` 渲染，
  包括拒绝理由、字段级校验消息、CSV 表头与导入模板表头。
- **FR-005**: 领域层 MUST NOT 自行格式化用户可见文本；它 MUST 返回目录键与参数，
  由 HTTP 边界渲染一次。
- **FR-006**: 两份目录的键集合 MUST 一致；任一条消息的**参数个数与顺序** MUST 一致。
- **FR-007**: 缺失的翻译 MUST 回退到默认语言；缺失的键 MUST 渲染为键本身 ——
  看得见的缺陷好过看不见的空白。
- **FR-008**: 标识符、日志、`error.code`、CSV 的键名行 MUST NOT 被翻译。
- **FR-009**: 日期与数字 MUST 按当前语言的习惯格式化。
- **FR-010**: 切换语言 MUST 丢弃已缓存的服务端响应。

### 持有方生命周期

- **FR-011**: 持有方 MUST 可编辑名称、备注与上级。类型 MUST NOT 可改。
- **FR-012**: 持有方 MUST 可删除；停用机制 MUST 移除，`archived_at` 列 MUST 一并移除。
- **FR-013**: 有设备持有或引用、有下级、或它是默认库存点时，删除 MUST 被拒绝，
  并 MUST 说明是什么挡着。
- **FR-014**: 仅在流转历史中出现 MUST NOT 构成拒绝理由；删除前 MUST 告知出现次数。
- **FR-015**: 删除 MUST 要求输入该持有方的名称才能确认。

## Success Criteria *(mandatory)*

- **SC-001**: 把浏览器语言设为英文，从登录到导出全程没有一个中文字符。
- **SC-002**: 任何一条服务端拒绝，两种语言下都能读懂且指向同一个动作。
- **SC-003**: 两份目录的键集合与参数序列由测试保证一致。
- **SC-004**: 删除一个用过的持有方之后，`nexus verify` 仍然全绿，流转历史一条不少。
- **SC-005**: 界面上不存在任何「停用持有方」的入口。

## Assumptions

- **只做中英两种**。用户说的是「中英双语」。目录的形状允许加第三种，
  但本轮不加，也不为此引入 ICU 或 gettext 之类的运行时。
- **服务端不做复数规则**。英文用 `device(s)` 而不是引入 ICU plural。
  两种语言、一个开发者的规模下，plural 库的成本大于收益；若日后加语言再谈。
- **持有方类型不可改**。把公司改成位置会让它的下级指向一个规则不允许的上级类型，
  而「那些下级怎么办」没有一个用户同意过的答案。删了重建把这件事说在明处。
- **切换语言会清空组件状态**。字典是模块级绑定，切换靠重挂整棵树传播。
  代价是半填的对话框会被清掉；这是一个一次会话里做几次的动作，可以接受。
