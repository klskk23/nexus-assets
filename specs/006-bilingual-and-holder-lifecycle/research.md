# Phase 0 Research: 中英双语与持有方生命周期

本文记录 7 项实现级决策。

---

## D1：服务端消息如何携带语言

**问题**：约 100 条中文消息散落在 20 多个领域文件里，多数是 `fmt.Errorf` 拼装的。
翻译它们不能靠给每个函数加一个 `lang` 参数 —— 那会污染整条调用链。

**决定**：领域层返回 **Message（键 + 参数）**，HTTP 边界渲染一次。

```go
type Message struct { Key string; Args []any }
func (m Message) Error() string  // 中文，供日志与测试
func (m Message) In(l Lang) string
func Wrap(sentinel error, key string, args ...any) error  // errors.Is 仍可用
```

**理由**：错误本来就要跨层往上传，把「用什么语言说」推迟到知道读者是谁的那一层，
是唯一不需要每层都知道语言的做法。`Wrap` 保留哨兵，因为 HTTP 层的 switch 靠它分派。

**唯一的例外**是导入预览与 CSV 导出：它们的产物是**为这一个请求构造的报表**，
不会向上传播，所以直接接收 `lang` 参数、当场渲染更简单。

## D2：消息的参数本身可能需要翻译

**问题**：「部门只能属于**公司**」里的「公司」也是要翻译的词。
如果在构造消息时就把它渲染成中文，整条消息就被冻结在中文里了。

**决定**：`Message` 自身实现 `In(Lang) string`，`Sprintf` 之前先把实现了该接口的参数
按目标语言展开。于是一条消息可以是另一条消息的参数。

配套的 `Join(sepKey, parts...)` 解决列表连接：「或」与 " or " 不可互换，
连接符本身也是文案。

**代价**：参数类型从 `string` 变成 `any`，读代码时看不出某个参数是不是可翻译的。
换来的是没有一处消息被半渲染。

## D3：目录一致性怎么保证

**问题**：两份目录漂移的表现是屏幕上出现一个裸键，而没有任何东西会报错。

**决定**：两条测试。

1. **键集合一致** —— 前端由 TypeScript 的 `typeof zh` 保证，服务端由测试保证。
2. **参数槽序列一致** —— 把 `%q` 归一为 `%s`（二者消费同一个字符串参数，
   加不加引号是排版选择），`%d`/`%v` 保留。

第 2 条**在写完目录的第一次运行就抓到一个真 bug**：
`holder.referenced` 中文是 `(name, total, parts)`，英文被写成了 `(name, parts, total)`。
类型系统看不见这种错误，只有渲染时才会把数字印在名字的位置上。

## D4：前端如何让几百处引用跟随语言

**问题**：457 处 `zh.xxx` 引用，28 个文件。

**考虑过的两条路**：

1. **hook**：`const { t } = useI18n()`。最符合 React 心智，但要在 28 个文件的
   每个组件体里插一行，且模块级常量（导航数组、流转动作数组）仍然要单独处理。
2. **模块级 live binding**（采用）：`export let t = ...`，切换时重新赋值。
   引用处只需把标识符从 `zh` 改名为 `t` —— 一次机械替换，由 typecheck 兜底。

**决定**：第 2 条，并把标识符从 `zh*` 改名为 `t*` —— 因为 `zh.assets.title` 在
双语之后是误导：那个对象是「当前语言」而不是「中文」。

**代价**：模块级绑定不是响应式的。`LanguageProvider` 通过 `key={lang}` **重挂整棵树**
来传播，于是切换语言会清空组件状态（半填的对话框）。这是一次会话里做几次的动作，
可以接受；代价写在 Provider 的注释里，不是隐含的。

**必须单独处理的**：在模块加载时求值的常量。有两处（导航数组、`transferActions`），
都改成了函数。它们不会被 typecheck 抓到 —— 用一个扫描顶层 `const` 的脚本找出来的。

## D5：`en` 字典如何与 `zh` 对齐类型

**问题**：`zh.ts` 用了 `as const`，`typeof zh` 因此是一堆字面量类型，
`const en: typeof zh` 会要求英文逐字等于中文。

**决定**：去掉 `as const`。字符串退化为 `string`，函数保留签名，
`typeof zh` 正好成为「字典的形状」。

**收益**：加一条中文而忘了加英文，是**编译错误**而不是运行时的 `undefined`。

## D6：默认语言的判定

**决定**：`localStorage` 的选择 > `navigator.language` 以 `en` 开头 > 中文。

**理由**：这是一家中文公司的系统，中文是默认而非并列。
不是英文的语言（法语、日语）落到中文而不是英文 ——
一个法语使用者更可能读得懂这套系统的中文术语（它们和界面里的数据混在一起），
也更可能身处这家公司。

**测试环境固定为中文**：jsdom 报告 `en-US`，而既有的 190 条断言是照中文写的。
在 `src/test/setup.ts` 里显式 `applyLang("zh")`，语言切换单独测。

## D7：持有方的删除为什么现在可以做了

**问题**：003 明确决定持有方**不**跟着改为可删除，理由是流转历史按 id 引用它。

**决定**：改为可删除，理由随 004 而变。

**核对**：004 决策 60 给状态确立了一条更细的规则 ——
**当前数据拒绝，历史记录提示**。历史引用不是「不能删」的理由，
而是「删了会退化成显示 id」的理由，退化的是可读性不是数据。
这条规则对持有方同样成立，而 003 当时还没有这条规则。

**新增的一条拒绝**是下级：静默把下级改挂到别处，等于替人改了组织架构。
`archived_at` 列一并移除 —— 一个没有任何代码能设置的列，
只会让下一个读者先花时间确认停用已经没了。
