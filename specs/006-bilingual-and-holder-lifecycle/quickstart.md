# 快速开始：中英双语与持有方生命周期

**Feature**: 006-bilingual-and-holder-lifecycle | **Date**: 2026-08-31

环境准备与开发流程沿用 [001 的 quickstart](../../001-asset-ledger-demo/quickstart.md)。

## 升级已有数据库

```bash
./nexus            # 启动时自动跑 migrations/006_holder_delete.sql
```

迁移只删掉 `holder_entities.archived_at`。**双语不需要迁移** —— 目录是代码。

## 切换语言

顶栏有一个语言按钮，上面写的是**将要切换到**的语言。第一次打开时跟随浏览器：
`en` 开头判英文，其余判中文。手动切过一次之后就记住，不再跟随系统。

切换会重挂整个界面，所以**没提交的对话框内容会被清掉**。这是模块级字典的代价，
写在 `web/src/i18n/useLanguage.tsx` 的注释里。

服务端也跟着变：每个请求带 `Accept-Language`，所以拒绝提示、CSV 表头、
导入模板表头都和界面同一种语言。**导入模板的第二行（键名行）永远不翻译** ——
那一行是给机器读的。

## 加一条文案

三处，缺一处都会被测试或编译抓到：

| 位置 | 加什么 | 漏了会怎样 |
|------|--------|-----------|
| `web/src/i18n/zh.ts` | 中文 | —— |
| `web/src/i18n/en.ts` | 英文 | **编译失败**（`typeof zh` 约束） |
| 组件里用 `t.xxx` | 引用 | 没引用的条目会被 `tests/i18n.test.ts` 报为遗留 |

服务端加一条：

| 位置 | 加什么 | 漏了会怎样 |
|------|--------|-----------|
| `internal/i18n/keys.go` | 键常量 | 编译失败 |
| `internal/i18n/catalog.go` 的 `ZH` | 中文 | 渲染出裸键 |
| 同文件的 `EN` | 英文 | `TestCatalogsCoverTheSameKeys` 失败 |

**参数个数与顺序两种语言必须一致**，由 `TestVerbSequencesMatchAcrossLanguages` 保证。
这条测试在写完目录的第一次运行就抓到一个真 bug。

## 加一个模块级常量时要当心

前端字典是模块级绑定，在模块**加载时**求值的东西不会跟着语言变：

```ts
const links = [{ label: t.nav.overview }]   // ✗ 冻结在首次加载的语言
function navLinks() { return [{ label: t.nav.overview }] }  // ✓
```

typecheck 不会发现。本轮改了两处（导航、流转动作）。

## 编辑与删除持有方

列表里每一行都有「编辑」和「删除」。编辑改名称、备注与上级；**类型不能改** ——
把公司改成位置会让它的下级指向一个规则不允许的上级类型。

删除在四种情况下被拒绝：有设备持有或引用、有下级、是默认库存点。
只在流转历史里出现过**不会**挡住删除，确认框会告诉你它出现过多少次；
删掉之后那些记录显示原始 id 而不是名字。

「停用」没有了。

## 排错

**界面英文但错误提示中文** —— 请求没带 `Accept-Language`，或某处没走 `LangOf(c)`。

**屏幕上出现一个裸键（如 `holder.parent_kind`）** —— 目录里缺这个键。
是可见的缺陷，不是空白，这是故意的。

**切换语言后半个页面没变** —— 那半个页面在模块级常量里冻结了字典，见上。
