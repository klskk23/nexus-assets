# Feature Specification: 持有方主从化，四个主从页拉齐

**Feature Branch**: `028-master-detail-holders`

**Created**: 2026-09-09

**Status**: Draft

**Input**: 持有方页改主从两栏；类别页补上分页与折叠，推翻 024 决策 152；新增持有方的批量计数与「含下级」筛选。

---

## 这一轮是什么

持有方是**最后一个还在用表格看层级**的元数据页。类别、字段、型号在 024 与 025 先后
改成了左树右详情，持有方留在 `CrudPage` 里 —— 而它是这四者中**唯一有强制层级规矩**
的一个（部门必须挂在公司下），用一张平表展示它，等于把它最要紧的那件事藏起来。

同时把类别页补上分页与折叠。那不是顺手做的第二件事，是同一件事的另一半：
四个页面走同一套形状件，其中一个缺两个零件，下一个读代码的人会以为那是有意的差别。

**本轮有服务端改动**（一个新端点、一个新筛选参数），七条合并门禁要真跑。

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 看清持有方的层级 (Priority: P1)

管资产的人打开持有方页，要回答的第一个问题是「我们有哪些地方能放设备，它们之间什么关系」。
今天他看到的是一张平表，「上级」是其中一列 —— 要在脑子里把二十行拼成一棵树。

改成左树右详情之后，公司、部门、位置的从属关系**就是画面本身**；点任何一个节点，
右边给出它的全部信息。

**Why this priority**: 这是这一页存在的理由。其余的故事都依附于它。

**Independent Test**: 造一棵三层的持有方（公司 → 部门 → 位置，外加一个无上级的位置），
打开 `/holders`，左栏应当画出这棵树而不是一张表；点任一节点，右栏显示该节点的详情。

**Acceptance Scenarios**:

1. **Given** 有「国药集团（公司）→ 研发部（部门）→ 三楼实验室（位置）」与一个无上级的
   「上海仓库（位置）」，**When** 打开 `/holders`，**Then** 左栏画出这棵树，
   「国药集团」与「上海仓库」并排在根一级，其余按 `parent_id` 缩进。
2. **Given** 左栏画好了，**When** 点击「三楼实验室」，**Then** 地址变为
   `/holders/<该节点 id>`，右栏显示它的类型、上级、备注与设备数。
3. **Given** 停在 `/holders/<id>` 上，**When** 刷新页面，**Then** 仍然选中同一个节点。
4. **Given** 一个人只有读权限，**When** 打开这一页，**Then** 树与详情**完整可见**，
   只是「修改」「设为默认库存点」两个按钮禁用并在悬停时说明缺哪个权限。

### User Story 2 - 一眼知道每处放着多少台 (Priority: P1)

盘库的人要知道「上海仓库现在放着多少台」。这个数必须**含下级**（问一个公司时，
答案要包括它底下所有部门和位置的设备），并且**含全部状态** —— 报废的设备还实实在在
堆在那个仓库里，等着处置。

**Why this priority**: 与故事 1 同级：一棵没有数字的树只回答了「有哪些地方」，
没回答「哪里是重点」。

**Independent Test**: 给一棵树的不同层级各放几台设备（含一台已报废），
核对每行的数字等于该节点子树内设备总数，且点进列表后行数与之相等。

**Acceptance Scenarios**:

1. **Given** 「国药集团」下有部门与位置合计 42 台设备（其中 3 台已报废），本身直接持有 0 台，
   **When** 看左栏，**Then** 「国药集团」那一行显示 **42**。
2. **Given** 右栏显示的是「国药集团」，**When** 点「看这里的 42 台设备」，
   **Then** 到达的资产列表**恰好有 42 行**。
3. **Given** 同一台设备既属于某个类别也放在某个持有方处，**When** 分别看类别页与持有方页，
   **Then** 两个数字可以不同（类别排除已报废，持有方不排除），
   且**两个数字不会在同一屏上顶着同一个词出现**。

---

### User Story 3 - 找到并设置默认库存点 (Priority: P2)

归还设备时，没有指定去处的设备会回到「默认库存点」。全系统**只有一个**。
今天要设置它，得先点开某一行的编辑对话框，在里面找到一个勾选框 —— 而「设为默认库存点」
是一个**独立权限**，与「修改持有方」不是一回事：只有修改权的人能勾上它、点保存、
然后吃一个拒绝。

**Why this priority**: 影响面小于前两个故事，但它是这一页**独有**的能力，
且现状是一个已知会误导人的入口。

**Independent Test**: 用一个只有 `holder.update` 的账号打开某个持有方，
「设为默认库存点」按钮应当禁用并说明原因，而不是让他试了才知道。

**Acceptance Scenarios**:

1. **Given** 「种子仓库」是当前的默认库存点，**When** 打开 `/holders`，
   **Then** 页头写着「默认库存点：种子仓库」，点它直接选中该节点（必要时翻到它所在那一页）。
2. **Given** 一个账号有 `holder.default_stock`，**When** 在右栏点「设为默认库存点」，
   **Then** 标记移到该节点，原来那个自动失去标记。
3. **Given** 一个账号有 `holder.update` 但没有 `holder.default_stock`，
   **When** 看右栏，**Then** 该按钮禁用并说明缺哪个权限 —— 不需要先点开编辑对话框才发现。
4. **Given** 选中的正是当前的默认库存点，**When** 看右栏，**Then** 按钮禁用并说明
   「换一个即可移走这个标记」（系统不接受「关掉」这个动作）。
5. **Given** 全系统还没有设过默认库存点，**When** 打开这一页，
   **Then** 页头说明这一点，因为不设置会让「归还」失败。

---

### User Story 4 - 删除一个持有方，并被告知代价 (Priority: P2)

持有方能不能删，取决于它有没有设备、有没有下级；即便都没有，它可能仍被流转历史提到。
今天这三个数在**页面打开的那一刻**就为每一行各问了一次，而删除按钮多数时候不会被点。

**Why this priority**: 功能已存在且能用，本轮改的是入口位置与代价的问法。

**Independent Test**: 打开一个有 20 个持有方的页面，观察不再有逐行的用量查询；
点开某个持有方的删除确认时，才出现对它一个的查询。

**Acceptance Scenarios**:

1. **Given** 页面上有 N 个持有方，**When** 打开这一页，
   **Then** 不再为每一个持有方各发一次用量查询。
2. **Given** 某个持有方底下还有下级，**When** 在编辑对话框里点删除，
   **Then** 拒绝，并**在同一个对话框里**列出挡路的是什么。
3. **Given** 某个持有方被 5 条流转历史提到但没有设备也没有下级，
   **When** 点删除，**Then** 确认框在删除**之前**说明这一点。
4. **Given** 树上任何一行，**When** 右键，**Then** 没有菜单 —— 编辑与删除只有一个入口。

---

### User Story 5 - 类别页与另外三页一致 (Priority: P3)

类别页今天没有分页也没有折叠。一个挂了六十个子类别的根，会把左栏其余部分挤出屏幕；
而字段页与型号页早已解决了同一个问题。

**Why this priority**: 改动小、风险低，但它是「四页拉齐」这句话成立与否的一半。

**Independent Test**: 造一个带 15 个子类别的根类别，打开类别页，
该节点应当默认折起并写明「15 个」；根节点多于一页时出现左栏的翻页控件。

**Acceptance Scenarios**:

1. **Given** 一个根类别有 15 个直接子类别，**When** 打开类别页，
   **Then** 该节点默认折起，行上写着有 15 个，点一下展开。
2. **Given** 根类别多于一页，**When** 翻到第二页，
   **Then** 页面上任何一行的父节点都在同一页上（不出现无出处的缩进）。
3. **Given** 折叠状态是本次浏览中的选择，**When** 把地址复制给同事，
   **Then** 对方打开时看到的是默认状态，不是我的折叠姿势。

### Edge Cases

- **一个持有方都没有**：左栏说明这一点并给出新建入口；右栏**不再重复**同一句话。
- **地址里的 id 不存在**（节点被别人删了、链接过期）：右栏说「找不到」，
  与「还没有任何持有方」是两句不同的话。
- **搜索命中两个同名的位置**（分属不同公司）：命中行显示完整路径，读者能分辨。
- **搜索时的层级**：一旦开始搜索就从树切成平展列表 —— 筛过之后的缩进没有出处。
- **公司下挂 60 个位置**：该节点默认折起，行上写明有多少个。
- **选中的节点不在当前页**：仍然显示在右栏（选中是一个 id，不是「本页的第几行」）。
- **窄屏**：先看树，选中后只看详情，返回入口回到 `/holders`。
- **报废设备所在的仓库**：计入该仓库的数字（这正是与类别页口径不同的地方）。
- **删除当前的默认库存点**：按既有守卫处理，本轮不新增规则。

## Requirements *(mandatory)*

### Functional Requirements

#### 左栏：树

- **FR-001**: 持有方页 MUST 以左树右详情两栏呈现，取代现有的表格。
- **FR-002**: 左树 MUST 按 `parent_id` 画出真实层级；公司与无上级的位置**并排在根一级**。
- **FR-003**: 每一行 MUST 标出该持有方的类型（公司/部门/位置）；
  MUST NOT 按类型把树切成三段。
- **FR-004**: 根一级 MUST 按名称排序，类型不参与排序。
- **FR-005**: 左栏 MUST 按根节点分页；一页之内，任何一行的父节点都在同一页上。
- **FR-006**: 单个节点的直接子项超过既定阈值时 MUST 默认折起，
  并在行上写明被折起的数量；折叠状态在本次浏览中保持，MUST NOT 写进地址。
- **FR-007**: 左栏顶部 MUST 提供搜索；搜索时 MUST 从树切换为平展列表，
  命中行 MUST 显示完整路径。
- **FR-008**: 左栏 MUST NOT 保留按类型筛选与按默认库存点筛选这两个控件。
- **FR-009**: 左栏底部 MUST 有一个「新建持有方」按钮；类型与上级在表单里选。
- **FR-010**: 树上的行 MUST NOT 提供右键菜单。

#### 计数

- **FR-011**: 每一行 MUST 显示该持有方的设备数，口径为**子树合计、含全部状态**。
- **FR-012**: 系统 MUST 用一次批量查询取得全部持有方的设备数，
  MUST NOT 为每个持有方各发一次请求。
- **FR-013**: 资产列表 MUST 支持按持有方筛选时**包含其下级**。
- **FR-014**: 右栏「看这里的 N 台设备」链接里的 N、左栏该行的数字、
  以及点进去之后列表的行数，三者 MUST 相等。
- **FR-015**: 持有方的计数口径与类别的计数口径**故意不同**，
  这一差异 MUST 写入 `docs/rules/`；两个数 MUST NOT 在同一屏上顶着同一个词出现。

#### 右栏

- **FR-016**: 右栏 MUST 显示：类型、上级、是否默认库存点。上级 MUST NOT 可点击。
- **FR-017**: 右栏 MUST 单独显示备注。
- **FR-018**: 右栏 MUST 提供一条到该持有方设备列表的链接，口径同 FR-011。
- **FR-019**: 右栏 MUST 提供「修改」按钮，打开现有的编辑对话框（表单不变，只换布局）。
- **FR-020**: 右栏 MUST 提供独立的「设为默认库存点」按钮，
  按 `holder.default_stock` 这一个权限判断是否禁用。
- **FR-021**: 选中项已经是默认库存点时，该按钮 MUST 禁用并说明标记只能移走、不能关闭。
- **FR-022**: 右栏 MUST NOT 列出直属下级（左树已经画了）。
- **FR-023**: 无相应权限时，右栏的按钮 MUST 禁用并在悬停时说明缺哪个权限，MUST NOT 隐藏。

#### 页头

- **FR-024**: 页头 MUST 写出当前的默认库存点，点击 MUST 选中它（必要时翻页到它所在页）。
- **FR-025**: 全系统没有默认库存点时，页头 MUST 说明这一点。

#### 删除与守卫

- **FR-026**: 删除入口 MUST 只在编辑对话框里；服务端拒绝时列出的阻挡项
  MUST 显示在同一个对话框内。
- **FR-027**: 删除的代价（有多少条流转历史提到它）MUST 在确认之前说明，
  且 MUST 只在打开该确认时查询，不在页面加载时为每一行预取。

#### 导航

- **FR-028**: 选中项 MUST 写进地址（`/holders/:id`），刷新与分享后仍指向同一节点。
- **FR-029**: 窄屏下 MUST 塌成一栏：先看树，选中后只看详情，返回入口回到 `/holders`。
- **FR-030**: 地址中的 id 不存在时，右栏 MUST 与「还没有任何持有方」区分开来。

#### 类别页

- **FR-031**: 类别页左栏 MUST 按根节点分页，规则同 FR-005。
- **FR-032**: 类别页左栏 MUST 按 FR-006 的同一规则折叠。
- **FR-033**: 类别页 MUST NOT 恢复右键菜单里的「展开/折叠子类别」两项。
- **FR-034**: 推翻 024 决策 152 的理由 MUST 写入 `docs/rules/web-tables.md`，
  写明这次为什么反过来。

#### 共用层

- **FR-035**: 本轮 SHOULD NOT 修改主从骨架。若发现必须修改，
  MUST 在交付说明中报告是什么迫使它改变，而不是顺手改掉。

---

### Key Entities

- **持有方（Holder Entity）**：公司、部门或位置。有名称、类型、可选的上级、备注，
  以及一个全系统唯一的「默认库存点」标记。层级规矩：公司无上级；部门必须挂在公司下；
  位置可挂公司或部门，也可以没有上级。
- **持有方设备数**：某个持有方**及其全部下级**当前持有的设备台数，不排除任何状态。
- **持有方用量**：删除一个持有方要付的代价 —— 直接持有的设备数（拒绝）、
  下级数（拒绝）、提到它的流转历史条数（仅警告）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 三层持有方（公司 → 部门 → 位置）的从属关系，
  在不点开任何东西、不横向滚动的情况下，从左栏一眼可读。
- **SC-002**: 同一个持有方，左栏行尾的数字、右栏链接文案里的数字、
  以及点进去之后列表的行数，**三者完全相等**；对根、中间层、叶子各验一次。
- **SC-003**: 打开持有方页时，用于计数的请求数**与持有方数量无关**（一次批量查询）。
- **SC-004**: 只有 `holder.update`、没有 `holder.default_stock` 的账号，
  在**不触发任何请求**的情况下就能看出自己不能设置默认库存点。
- **SC-005**: 主从骨架（`MasterDetail` / `useMasterSelection`）在本轮**零改动**；
  这是第四个调用方进来。
- **SC-006**: 类别页与字段页、型号页在分页与折叠上的行为**无法从操作上区分**。
- **SC-007**: 备注在持有方右栏可见 —— 025 曾把型号备注连同它的测试一起删掉，
  本轮必须有测试守着这一条。
- **SC-008**: 七条合并门禁全部通过，含服务端的 `go test ./...`、`gofmt`、`go vet`、
  `nexus verify`；核心管线覆盖率不低于 80%。

## Assumptions

- **持有方的规模是几十到几百**，不是几万；分页与折叠按这个量级取参数（沿用字段/型号页的阈值）。
- **持有方最深三层**，由既有的层级规矩保证；搜索的完整路径因此靠现有的上级关系推导，
  不需要为它新增存储。
- **默认库存点全系统唯一**，且只能被「移走」不能被「关掉」—— 这是既有的服务端行为，本轮不改。
- **「持有方」在本页专指实体**（公司/部门/位置）。设备也可以由某个账号持有，
  那一侧不在这一页管理，本轮不做。
- **编辑表单不变**，本轮只改它的打开方式与周围的布局。
- **`archived_at` 那一列继续不动**：有列、读取时也扫，但没有任何代码写过它（024 决策 10）。
- 本轮不做：停用/归还期限、持有方的字段绑定、把用户并入这棵树。
