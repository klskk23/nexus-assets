# 走查脚本：028

演示库里**只有 1 个持有方、4 个类别**，两个阈值都是 12 —— 照现状走查，
分页与折叠一次也不会显形，计数永远是「一个数对一个数」。**先造数据再走查。**

## 0. 造一棵能触发所有分支的树

```
国药集团（公司）
├── 研发部（部门）
│   └── 三楼实验室（位置）        ← 放 2 台，其中 1 台报废
├── 种子仓库（位置，默认库存点）   ← 放 3 台
└── ……再补 12 个位置             ← 触发「超 12 折起」
上海仓库（位置，无上级）           ← 放 1 台
外包机房（位置，无上级）           ← 放 0 台
……再补 12 个无上级的位置          ← 触发根分页
```

要点：**必须有一个 0 台的节点**（验「0 也写出来，不留白」）、
**必须有一台报废设备**（验持有方口径含它、类别口径不含它）。

## 1. 计数三者相等（SC-002，最要紧的一条）

对**根、中间层、叶子各一次**：

1. 记下左栏该行的数字。
2. 点右栏「看这里的 N 台设备」，核对文案里的 N 与第 1 步相同。
3. 数到达列表的总数，与前两者相同。

**「国药集团」那一行必须是子树合计**（它自己直接持有 0 台，若显示 0 就是没上卷）。

## 2. 两种口径故意不同

把那台报废设备放在「三楼实验室」：

- 持有方页的「三楼实验室」**计入它**。
- 类别页对应类别的数字**不计入它**。

两个数字不同是对的。**同时确认这两个数不在同一屏上顶着同一个词出现。**

## 3. 树的形状

- 「国药集团」与「上海仓库」**并排在根一级**（公司不置顶，按名字排）。
- 「研发部」缩进一层，「三楼实验室」缩进两层。
- 「国药集团」子项超 12 → **默认折起**，行上写着有多少个；点三角展开。
- 根多于 12 → 左栏底部出现 `1 / 2` 的翻页条；翻到第二页，**页面上任何一行的父都在同一页**。

## 4. 搜索

1. 搜「实验室」→ 从树切成**平展**列表。
2. 命中行显示**完整路径**「国药集团 / 研发部 / 三楼实验室」。
3. 搜索词写进地址；刷新后仍是平展态。
4. 清空搜索 → 回到树。

## 5. 默认库存点（三条都要走）

1. 页头写着「默认库存点：种子仓库」，**点它直接选中该节点**。
2. 选中「种子仓库」→ 右栏按钮**禁用**，说明「换一个即可移走这个标记」。
3. 选中「上海仓库」→ 点「设为默认库存点」→ 标记移过来，**页头那一行跟着变**，
   「种子仓库」自动失去标记。

## 6. 权限（不点就能看出来）

用只有 `holder.update`、没有 `holder.default_stock` 的角色登录：

- 「修改」可用。
- 「设为默认库存点」**禁用**，悬停说明缺哪个权限。
- **关键**：这一切在**不发出任何请求**的情况下就看得出来 —— 不需要点了才知道。

用只有读权限的角色：树与详情**完整可见**，两个按钮都禁用。

## 7. 删除与 N+1

1. 打开持有方页，**看网络面板**：不应有 N 个 `/holders/{id}/usage`。
   应当只有一次 `/holders/counts`。
2. 打开某个持有方的编辑对话框 → 点删除 → **此时**才出现一次 `usage` 请求。
3. 删一个有下级的 → 拒绝，**阻挡项列在同一个对话框里**。
4. 删一个被流转历史提到的 → 确认框在删之前说明有多少条。
5. **树上右键 → 没有菜单。**

## 8. 导航

- 点节点 → 地址变 `/holders/<id>`；刷新仍选中它。
- 手改成一个不存在的 id → 右栏说「找不到」，**与「还没有任何持有方」是两句不同的话**。
- 窄屏（<768px）→ 先看树，选中后只看详情，返回入口回 `/holders`。

## 9. 类别页（这一半是「证明它已经在了」）

- 造 13 个子类别挂在一个根上 → **默认折起**并写明数量。
- 造 13 个根类别 → 出现翻页条。

若这两条走查不出来，那就是 research 第一节的结论错了，回去重查。
