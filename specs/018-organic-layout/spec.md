# Feature Specification: Organic 版面重做

**Feature Branch**: `018-organic-layout`

**Created**: 2026-09-08

**Status**: Draft

**Input**: 把页面版面重排成 Organic 的排版方式 —— 贴左的内容列、三档地面各归各位、
拉丁与中文分工的字号层级、56px 的分区节奏、数量画成轨道。规格参照在
`docs/design/organic-layout/`（`handoff.md` 为规范正文）。决策 122–129。

> **语言规范**（章程原则 V）：本规格的全部正文内容必须使用**中文**撰写。
> 仅以下内容保留英文：API 路径与参数名、字段 key、错误码 `error.code`、
> 数据库标识符。用户可见文案（UI 文本、字段 label、`error.message`）使用中文。

## 这一轮与 017 的分工

017 换的是**主题**：令牌值、药丸、圆角、自托管字体、深色下架。开发者看完的评价是
「你实际上只修改了主题而不是页面布局」—— 这话是对的。017 没有碰**空间系统**：
内容列**没有上限**（017 拿掉居中列时没有换上别的边界，宽屏上一路顶到右边）、
分区仍是 24px、表格行仍是 36px、28px 的圆角贴着 8px 的内边距。
八个元数据页一行没改，还被当成成绩报了上去。

这一轮换的是**版面**。参照稿明确写着「**没有引入任何新令牌**」——
`web/src/index.css` 的颜色值不动，改的是这些值被排布的方式。

## 本轮不做什么

| 不做的 | 为什么 |
|---|---|
| 新增或改动颜色令牌 | 参照稿的令牌表就是 017 的现状，一个值都不改 |
| 深色主题 | 参照稿的审视第 4 条与文末待决项要求产品决定，017 已经整套拆除。**这一条已经关闭** |
| 领域模型、迁移、服务端 | 本轮零 Go 改动、零迁移、零端点变化 |
| 拆掉 017 的资产页选择模型 | 参照稿的 `AssetList` 只画了六列，是因为它对着 017 之前的 GitHub 代码做的（017 当时未推）。**没画不等于反对** |
| 新增路由 | 参照稿的九屏里，`Custody` 指向 `TransferForm`/`ActionBar`，`PrintLabels` 指向 `PrintDialog` —— 都是现有组件，不是新页面 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 版面读起来是一套系统（Priority: P1）

管理员在页面之间走动，每一页的留白节奏、内容列位置、地面分工、圆角与字号层级
都是同一套。内容贴左、**宽度有上限**、右侧留白 —— 而不是一路铺到窗口右边。

**Why this priority**: 这是开发者提出的问题本身。视觉令牌已经统一，版面还没有 ——
半套 Organic 比不做更刺眼，因为颜色在暗示一种排版方式而骨架在做另一种。

**Independent Test**: 逐页打开十八个路由，量三件事：内容列是否贴左且有上限、
分区之间是否 56px、圆角容器的内边距是否 ≥24px。

**Acceptance Scenarios**:

1. **Given** 任意一个内容页，**When** 查看主区，**Then** 内容列贴左、宽度有上限
   （常规 960px、正文类 760px、表单 620–640px），右侧是留白而不是一路铺到窗口边
2. **Given** 任意一个内容页，**When** 量分区之间的距离，**Then** 是 56px，
   而不是与区内成组相同的 24px
3. **Given** 任意一个圆角 28px 的容器，**When** 量它的内边距，**Then** ≥24px ——
   半径 28 的角需要这么多空气才不切到内容
4. **Given** 任意一页，**When** 数页面上出现的底色，**Then** 只有三档
   （页面、下沉、浮起），没有第四种

### User Story 2 - 三档地面各归各位（Priority: P1）

浮起来的东西看起来是浮起来的，压下去的东西看起来是压下去的。

**Why this priority**: 这是版面里最容易做反的一条，而做反了整页的层次都会读错。
`--card`（#ebddc5）比 `--background`（#f5ead8）**深**，`--well`（#f9f4ed）比两者都**浅** ——
在中性主题里「卡片=抬起」的直觉在这套令牌下是反的。017 正是在这里做反了：
侧栏与表格框都用了 `--card`。

**Independent Test**: 全站搜 `bg-card`，命中的每一处都必须是真正浮在页面之上的东西。

**Acceptance Scenarios**:

1. **Given** 一个对话框、抽屉或悬浮卡，**When** 查看它的底色，**Then** 是 `--card`
2. **Given** 一张表格，**When** 查看它的容器，**Then** 表格**不坐在卡片上**，
   表头坐在 `--well` 上
3. **Given** 概览页的状态卡，**When** 查看它的底，**Then** 是页面地面色
   加一圈 `--border-muted` 描边，而不是卡片底
4. **Given** 任意页面的分区之间，**When** 查看，**Then** 用留白分隔，
   没有为分区引入第四种底色

### User Story 3 - 中文标题终于有层级（Priority: P1）

页面标题在视觉上明显大于区标题，区标题明显大于正文 —— 中文也是。

**Why this priority**: 017 把 `font-heading`（Caprasimo）挂在中文 h1 上。
Caprasimo 只有拉丁子集，中文必然落到 Noto Sans SC，**那一行什么也没做**。
所以现在中文页面标题与区标题的差别只有 24px 对 16px，读不出层级。

**Independent Test**: 打开任意中文页面，页标题、区标题、正文三级在不看颜色的
情况下能一眼分出。

**Acceptance Scenarios**:

1. **Given** 一个中文页标题，**When** 查看，**Then** 是 40px/1.2/700，
   由字号与字重建立层级，不依赖一个渲染不出来的字体
2. **Given** 产品名、页码、计数、资产编号、字段键名，**When** 查看，
   **Then** 用 Caprasimo —— 它们全是拉丁与数字，是这个字体管得住的字符
3. **Given** 任意列里的数字，**When** 查看，**Then** 等宽对齐（`tabular-nums`）

### User Story 4 - 列表页可读（Priority: P1）

管理员扫一列资产编号时，行与行之间有呼吸，表头与数据分得开。

**Why this priority**: 列表是这个产品的主要形态 —— 十八个路由里十个是表格。
行高 36px 配 28px 的圆角与 56px 的分区，是整套里最不协调的一处。

**Independent Test**: 打开资产列表与任意元数据页，量行高与表头底色；
确认 017 的选择模型一件不少。

**Acceptance Scenarios**:

1. **Given** 任意表格，**When** 量行高，**Then** 48px，行分隔是 `--border-muted`
2. **Given** 资产列表，**When** 查看，**Then** 勾选列、全选框、「选中符合当前筛选的
   全部 N 条」横幅、Shift 连选、行尾三个悬浮按钮、底部批量条**全部还在**，
   只是按新的尺寸重排
3. **Given** 八个元数据页中的任意一个，**When** 打开，**Then** 它们与状态页
   同一形态 —— 改的是共用件，不是逐页各改一遍
4. **Given** 任意表格，**When** 右键一行，**Then** 操作菜单照旧；
   **When** 点击一行，**Then** 进编辑或详情。单元格里仍然没有可点击控件

### User Story 5 - 概览一屏读完（Priority: P2）

管理员登录后落在概览，五个状态、类别分布、最近流转在一屏里读得完。

**Why this priority**: 概览是登录后的第一屏，也是数量图形集中出现的地方 ——
颜色被状态占满之后，形状是数量唯一还能用的维度。

**Independent Test**: 打开概览，确认状态卡是可点的地面色块、类别分布是药丸轨道、
最近流转是带鼠尾草圆点的行列表。

**Acceptance Scenarios**:

1. **Given** 概览页，**When** 查看设备状态，**Then** 五个横向排列的可点区块，
   每个最小 152px，上方状态芯片、下方 Caprasimo 大计数；计数为 0 时数字退到次要色
2. **Given** 概览页，**When** 查看类别分布，**Then** 每行是「类别名 + 药丸轨道 + 右对齐计数」，
   轨槽是下沉色、填充是鼠尾草，且**整行可点**并跳到按该类别筛选的列表
3. **Given** 概览页，**When** 查看最近流转，**Then** 每行左侧一个鼠尾草圆点，
   行与行之间是细分隔线；批量操作折成一条并标出台数

### User Story 6 - 详情与流转（Priority: P2）

管理员点开一台设备，属性成网格铺开、流转历史是一条时间线；做流转时表单是一列，
不铺满整个宽度。

**Why this priority**: 详情是列表之外访问最频繁的界面；流转是这个产品的核心动作。

**Acceptance Scenarios**:

1. **Given** 资产详情，**When** 查看页头，**Then** 标题就是资产编号本身
   （Caprasimo、等宽数字），旁边一个状态芯片
2. **Given** 资产详情，**When** 查看设备属性，**Then** 四列网格（窄屏降两列），
   整块坐在下沉色上，圆角 28px、内边距 ≥24px；键名小字、值正常字号
3. **Given** 流转表单，**When** 查看，**Then** 表单列 620–640px 贴左，
   字段一律走表单组件，控件高 48px

### User Story 7 - 登录页贴左（Priority: P2）

第一次打开这个产品的人看到的是一个有主张的版面，不是一张居中的卡片。

**Why this priority**: 登录是唯一一屏没有导航、没有数据、可以自由排版的页面。
把它做成居中卡片，等于放弃了唯一一次自我介绍的机会。

**Acceptance Scenarios**:

1. **Given** 登录页，**When** 查看，**Then** 左列表单（上限 420px）、右列装饰，
   之间 64px，垂直居中
2. **Given** 登录页，**When** 查看产品名，**Then** Caprasimo 52px/1.05 两行
3. **Given** 登录页，**When** 查看右侧装饰，**Then** 是几个重叠柔形，
   `aria-hidden`，**没有借用任何状态色槽**
4. **Given** 登录页，**When** 提交之前，**Then** 域名限制说明仍然可见 ——
   它是 v1 唯一的准入边界

### User Story 8 - 打印对话框（Priority: P3）

管理员勾选一批设备打标签时，看得清会产生几个作业、消耗哪段序号。

**Acceptance Scenarios**:

1. **Given** 打印对话框，**When** 查看，**Then** 上限 620px、`--card` 底
   （它确实是浮起的）、圆角 28px、内边距 32px
2. **Given** 打印对话框，**When** 查看提示块，**Then** 下沉色底、圆角 20px，
   说清会产生几个作业与消耗的序号段
3. **Given** 作业列表，**When** 查看进度，**Then** 药丸进度轨用鼠尾草 ——
   它数的是**张数不是状态**；只有「失败」那一行用状态红，因为它确实是一个状态

### User Story 9 - 没画的三页跟上（Priority: P3）

导入、审计、全量历史与其余十五个路由在同一套节奏里。

**Why this priority**: 参照稿没有画这三页。它们不跟上，就会成为整轮里
一眼看得出的三块补丁（行高 36 对 48、分区 24 对 56）。

**Acceptance Scenarios**:

1. **Given** 这三页中的任意一页，**When** 与相邻页面对比，**Then** 行高、分区间距、
   内容列宽度、地面分工一致
2. **Given** 审计页，**When** 查看前后值，**Then** 新旧仍然可分且**不只依赖颜色**
3. **Given** 类别页，**When** 不搜索，**Then** 仍是缩进的树；
   **When** 搜索，**Then** 切平铺显示完整路径。**名称格里仍然没有行内箭头**

### Edge Cases

- **中文与拉丁混排的标题**：资产编号是拉丁数字走 Caprasimo，页标题是中文走
  Figtree/Noto —— 同一个页头里两种字体并存时，基线与字重观感必须协调
- **窄屏**：内容列是上限不是固定宽；详情属性网格四列降两列；
  所有横向成组用 flex-wrap。参照稿没有做移动端断点，本轮不新增断点
- **空表格**：48px 的行高不适用于空态；空态仍然要说清什么会填满它，
  被筛空了要给出清除筛选
- **超长类别名**：分布条的类别名列宽固定，过长要截断而不是把轨道挤没
- **零计数**：状态卡计数为 0 时数字退到次要色，但区块本身仍然可点
  （筛出零条也是一个有效结果）
- **焦点环换机制**：参照稿要 `outline` + offset，017 用的是实心 `box-shadow` ring。
  换过去之后**必须重新量对比度**，不能假定换个机制数字还成立
- **英文界面**：所有尺寸在英文下也要成立 —— 英文比中文长，
  48px 行高与固定列宽在英文下不得溢出

## Requirements *(mandatory)*

### Functional Requirements

**空间系统**

- **FR-001**: 内容区 MUST 贴左排布并**设上限**（常规 960px、正文类 760px、
  表单 620–640px）。
  参照稿把现状写成「`mx-auto max-w-7xl` 的居中列」，那是 017 之前的事实 ——
  居中列早已不存在，现状是**没有任何上限**。要加的是上限本身。
- **FR-002**: 分区之间的距离 MUST 是 56px（登录页 64px），区内成组 22–24px
- **FR-003**: 圆角 28px 的容器内边距 MUST ≥24px
- **FR-004**: 表格行高 MUST 是 48px，行分隔 MUST 用 `--border-muted`
- **FR-005**: 侧栏宽度 MUST 是 236px；控件高 MUST 是 48px（登录页 50px）
- **FR-006**: 圆角 MUST 只有三档：容器 28px、下沉块与提示块 20px、一切小控件 999px

**地面分工**

- **FR-007**: `--card` MUST 只用于真正浮在页面之上的东西（对话框、抽屉、悬浮卡）
- **FR-008**: 下沉面（表头、只读值组、时间线行底）MUST 用 `--well`
- **FR-009**: 页面分区 MUST 用留白分隔，MUST NOT 引入第四种底色
- **FR-010**: 表格 MUST NOT 坐在卡片底上

**字体分工**

- **FR-011**: Caprasimo MUST 只用于它有字形的字符：产品名、页码、计数、
  资产编号、字段键名。MUST NOT 用于中文标题
- **FR-012**: 中文标题的层级 MUST 由字号与字重建立（页标题 40px/1.2/700，
  区标题 21px/700）
- **FR-013**: 列中的数字 MUST 等宽对齐

**颜色分工（沿用 017，不改）**

- **FR-014**: 陶土 MUST 只表示动作，鼠尾草 MUST 只表示数量，
  八个状态色槽 MUST 只表示状态。装饰只能用 `--muted`、`--well`、`--border`
- **FR-015**: 数量 MUST 画成药丸轨道或圆盘，MUST NOT 用直角条

**交互与状态**

- **FR-016**: 每个可交互元素 MUST 有 `--accent` 的悬停浅底
- **FR-017**: 焦点指示 MUST 达到 WCAG 1.4.11 的 3:1，**换成 outline 机制后
  MUST 重新测量**，不得沿用 017 的测量结论
- **FR-018**: 不可用的动作 MUST 禁用**并说明缺什么**，MUST NOT 隐藏

**017 的交互一件不少**

- **FR-019**: 资产页的选择模型 MUST 全部保留：全选本页、选中符合筛选的全部 N 条、
  Shift 连选、行尾单台操作、底部批量条
- **FR-020**: 行本身 MUST 是点击目标，单元格里 MUST NOT 放可点击控件
- **FR-021**: 翻页 MUST 仍在表格下方一行，含区间、页码、每页条数
- **FR-022**: 筛选与翻页 MUST 继续写入地址栏，且用替换而非压栈
- **FR-023**: 层级 MUST 用缩进表达，名称格里 MUST NOT 放行内箭头

**范围**

- **FR-024**: 八个走共用件的元数据页 MUST 通过改造共用件一次性获得新版面，
  MUST NOT 逐页各改一遍
- **FR-025**: 参照稿未覆盖的三个路由（导入、审计、全量历史）MUST 按同一套规范推导，
  并在完成后交开发者确认
- **FR-026**: 本轮 MUST NOT 新增或改动颜色令牌，MUST NOT 引入数据库迁移，
  MUST NOT 改变任何领域规则或端点

**贯穿约束**

- **FR-027**: 所有用户可见文案 MUST 同时具备中英两种语言
- **FR-028**: 触及界面的改动 MUST 附带相应的界面测试；既有测试中因改造而失效的
  MUST 更新而非删除
- **FR-029**: 对话框内发生的拒绝 MUST 显示在对话框内部
- **FR-030**: 空状态 MUST 说清什么会填满它；被筛空时 MUST 提供清除筛选

### Key Entities

本轮不引入新的领域实体，也不改变任何既有实体。涉及的只是这些实体的**呈现**。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 十八个路由逐页检查，**没有一页**的分区间距、行高、内容列宽度
  或地面分工与规范不符
- **SC-002**: 全站 `bg-card` 的每一处命中都是真正浮起的东西（对话框、抽屉、悬浮卡）
- **SC-003**: 中文页面上，页标题、区标题、正文三级在不看颜色的情况下可分
- **SC-004**: 焦点指示在四种底色（页面、卡片、下沉、次级）上**实测**均 ≥3:1
- **SC-005**: 017 的资产页选择模型七项行为**一项不少**，既有的 7 条回归测试全过
- **SC-006**: 界面测试全部通过；因版面改动而失效的测试是更新的，不是删除的
- **SC-007**: 英文界面逐页走查，没有文字溢出、没有药丸内换行、没有列被挤没
- **SC-008**: 键盘可达性不低于改造前：每个可交互元素 Tab 到得了，焦点始终可见
- **SC-009**: 本轮的 Go 代码改动为**零行**，迁移为**零个**，端点变化为**零处**

## Assumptions

- **参照稿的尺寸是最终值。** `handoff.md` 声明 high-fidelity，颜色、字号、间距、
  圆角、交互状态都是最终值；只有数据是示意用的假数据。冲突时以 `handoff.md` 为准
  （它自己这么写的），单屏细节以同名 `.dc.html` 为准。
- **参照稿的三处前提偏差已知并已记录**（见 `docs/design/organic-layout/README.md`）：
  它的令牌表是 017 之后的，页面事实是 017 之前的。凡是它描述「现状」的地方，
  以仓库实际为准；凡是它规定「应当」的地方，以它为准。
- **侧栏留一处待定。** 参照稿交付了一版侧栏，同时列出四条自己认为该改的地方，
  其中第一条正是全局规则第 2 条本身。本轮**两版都实现并截图**，由开发者裁定。
  这是本轮唯一一处刻意不预先决定的地方。
