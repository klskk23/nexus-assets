# 实机走查：字段组与厂商实体

起一个本地实例，按顺序走完。第 1、2 步是迁移，必须在**含存量数据**的库上做，
不能只在空库上过 —— 015 那轮的第 10 步就是在实机上才暴露出导出读了归档值。

```
CGO_ENABLED=0 go build -o /tmp/nexus ./cmd/nexus
NEXUS_JWT_SECRET=... NEXUS_ADMIN_EMAIL=... NEXUS_ADMIN_PASSWORD=... \
NEXUS_DB_PATH=/tmp/qs.db /tmp/nexus seed 40
```

---

**1. 迁移在含大小写不一致厂商名的既有库上跑通。**
迁移前手工插入三款型号：`(Dell, X1)`、`(DELL, X1)`、`('', X1)`。
迁移后：三个厂商实体（`Dell`、`DELL`），第三款 `vendor_id` 为 NULL，三款型号都在。
**不允许**归并成两款。

**2. 折叠后的唯一约束仍然拦得住。**
迁移后再插一款 `vendor_id = NULL, name = X1` → 被唯一索引拒绝。
这一条是迁移 003 修的 bug 的回归。

**3. 读 `model.vendor` 的表达式，迁移前后算出同一个值。**
迁移前建一个计算字段 `upper(model.vendor)`，记下某台设备的值；
迁移后重算，值不变。这是 research.md 第二节点名的那处硬要求。

**4. 厂商字段流向旗下全部型号。**
建厂商 Dell 与三款型号；建字段 ServiceTag 绑到 Dell；
`GET /api/categories/:id/schema` 里出现 ServiceTag，且 `vendor_ids=["Dell"]`、
`model_ids` 是那三款、`binding_mode="device"`。

**5. 新建的型号开箱即有。**
接第 4 步，新建第四款 Dell 型号，不做任何别的操作 →
录入这款型号的设备时，表单里有 ServiceTag。

**6. 厂商已提供的型号，勾选框是禁用的。**
在字段编辑器里给 ServiceTag 选设备模式 → 那三款 Dell 型号的勾选框禁用，
悬停说明「厂商 Dell 已经提供了这个字段」；别家厂商的型号仍可勾。

**7. 类别与设备侧仍然互斥。**
把 ServiceTag 再绑到某个类别 → 拒绝。把一个类别字段绑到厂商 → 拒绝。
把 ServiceTag 同时绑到 Dell 与一款联想型号 → **允许**。

**8. 唯一性范围是厂商旗下全体。**
把 ServiceTag 标为唯一，在两款不同的 Dell 型号上各录一台设备、填同一个值 → 第二台被拒。

**9. 绑组是原子的。**
建组「网络参数」含 mac、firmware，其中 mac 已绑在某类别上；
把该组绑到一个型号 → 整体拒绝，点名 mac；
`GET /api/fields` 确认 firmware **没有**被绑上去。

**10. 组绑成功后与逐个绑等价。**
换一个全部成员都合法的组，绑到型号 → 该型号的有效字段集与逐个绑三次完全一致。

**11. 删除组不动已展开的绑定。**
删掉第 10 步的组 → 那个型号的字段一个不少。

**12. 改厂商先告知，再归档。**
给某型号的 30 台设备填上 ServiceTag；把该型号厂商从 Dell 改成联想 →
保存前告知 30 台；确认后查其中一台，ServiceTag 在已归档字段里只读可见。

**13. 筛选。**
资产页按厂商筛 → 只剩该厂商的设备，且筛选进地址栏；
资产页的筛选栏里**没有**「组」；
字段页按组筛、按厂商筛各自正确。

**14. 导入的 vendor 列查不到就拒绝该行。**
CSV 里写一个不存在的厂商名 → 预览阶段该行报错，且 `GET /api/vendors` 里没有新增。

**15. 既有行为回归（015 及更早）。**
`GET /api/categories` 仍是数组（zenith 的数据源按数组解析）；
类别绑定、型号绑定、导入导出、列解锁、`nexus verify` 全部照旧。
