# Feature Specification: 术语更名与录入时的持有方与负责人

**Feature Branch**: `001-asset-ledger-demo`（沿用主开发分支，未另开分支）

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "1. 信息项更名为字段 2. 录入设备时也应该需要选择持有方和用户，
如果持有方已经是用户了，就不需要再选择用户。"

> **与既有规格的关系**：本规格更名一个贯穿 001–008 的术语，并补齐录入表单的一个缺口。

| 既有需求 | 本规格的处置 |
|----------|--------------|
| 001–008 通篇的「信息项」 | **更名** → FR-001：统一为「字段」 |
| 001：录入时负责人恒为当前登录账号 | **取代** → FR-004~FR-007 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 术语统一为「字段」 (Priority: P1)

界面上到处写着「信息项」，而代码里、开发者口中、以及绑定到类别上的那一列，
说的都是「字段」。一个东西两个名字，读文档的人要先做一次翻译。

**Independent Test**: 中英界面各走一遍，确认不再出现「信息项」/「information item」。

**Acceptance Scenarios**:

1. **Given** 中文界面的任意页面，**Then** 不出现「信息项」
2. **Given** 英文界面，**Then** 不出现 "information item"
3. **Given** 服务端返回的任何拒绝，**Then** 两种语言都用新称呼
4. **Given** 001–008 的规格与设计基线，**Then** 保持原文不动 ——
   它们是当时写下的记录；CLAUDE.md MUST 说明新旧对应，读历史文档的人才对得上
5. **Given** 代码中的标识符，**Then** 无需改动（一直是 `field`）

---

### User Story 2 - 录入时说清谁持有、谁负责 (Priority: P2)

录入一台设备时，负责人固定是正在操作的那个人 —— 哪怕设备一进门就是交给张三的。
现在两者都能选；而如果持有方本来就是某个账号，就不再多问一遍。

**Independent Test**: 录入时把持有方选成某个账号，确认负责人选择消失，
且保存后该账号既是持有方也是负责人。

**Acceptance Scenarios**:

1. **Given** 录入对话框，**Then** 持有方下拉同时提供实体与账号，分组显示
2. **Given** 持有方选了一个实体，**Then** 出现负责人选择，默认当前登录账号
3. **Given** 持有方选了一个账号，**Then** 负责人选择消失
4. **Given** 上述情况提交，**Then** 该账号既是持有方也是负责人
5. **Given** 已停用的账号，**Then** 既不出现在持有方里，也不出现在负责人里
6. **Given** 持有方或负责人为空，**Then** 保存按钮不可用
7. **Given** 一台新录入的设备，**Then** 它的默认归属仍是录入时的持有方与负责人（007 不变）

## Requirements *(mandatory)*

### 术语

- **FR-001**: 用户可见文案中的「信息项」MUST 更名为「字段」，英文对应 "field"。
- **FR-002**: 更名 MUST 覆盖前端与服务端两份目录。
- **FR-003**: 001–008 的规格与设计基线 MUST NOT 改动；CLAUDE.md MUST 记录新旧对应。

### 录入

- **FR-004**: 持有方 MUST 可以是任意启用账号或任意持有方实体，分组呈现。
- **FR-005**: 持有方是实体时 MUST 提供负责人选择，默认当前登录账号。
- **FR-006**: 持有方是账号时 MUST NOT 提供负责人选择；该账号即负责人。
- **FR-007**: 已停用的账号 MUST NOT 出现在任一下拉中。
- **FR-008**: 持有方或负责人未定时，保存 MUST 不可用。

## Success Criteria *(mandatory)*

- **SC-001**: 中英界面与服务端消息中都不再出现旧称呼。
- **SC-002**: 录入时把设备直接交给某个人，一次操作即可，且不必回答一个已知的问题。
- **SC-003**: 读 001–008 的规格时，能从 CLAUDE.md 对上新旧术语。

## Assumptions

- **数据库标识符与代码不改。** 它们一直是 `field` / `field_definitions`，
  这次更名让文案追上代码，而不是反过来。
- **旧规格不回溯改写。** 它们是当时的记录。改掉会让「这一轮改了什么」变得不可读，
  而对应关系写在一处就够了。
