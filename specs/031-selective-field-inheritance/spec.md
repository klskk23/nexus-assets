# 功能规格：类别字段可选继承

**创建日期**：2026-09-30

**状态**：本轮实施与验收已完成（`tasks.md` 69/69）；实际证据、测量边界及性能偏离见 `verification.md` 与 `plan.md`。未推送、打 tag 或发布，不代表生产迁移授权。

**输入**：子类继承字段改为可选继承；以下规则均来自本轮逐项确认及整体设计定稿。

**范围**：类别字段继承的数据模型、解析、变更事务、编辑界面及所有有效字段消费者。

## 背景与目标

当前类别字段在读取时沿祖先路径自动合并，子类只能追加，不能决定继承哪些字段。父类增加字段会立即影响全部后代。

本轮改为逐字段、正向选择：子类只能从直接父类当前有效的字段中选择；自身直接绑定始终保留。祖父字段只有先被父类继承，才能继续传给子类。继承是动态来源关系，不是把祖先绑定复制成自己的直接绑定。

升级保留现有结果，但不保留旧的自动继承模式：迁移把现有继承字段回填为已选择；迁移后，新旧类别都只继承明确选中的字段。新建子类默认不选，父类后来新增字段也默认不选。

### 本轮不做

- 不改变型号与厂商的实时字段传播，不恢复型号与类别的关联。
- 不允许子类覆盖字段的类型、键、必填、唯一或计算公式。
- 不放开同一祖先链上的同 key 冲突，不引入同 key 替代字段或属性身份迁移。
- 不把类别详情改成可编辑字段表，不把直接绑定管理搬进类别编辑器。
- 不新增类别停用，不放宽现有类别移动限制，不修改状态、持有方或权限模型。
- 不重做跨类别导出形状，不增加新的主题、自定义组件或框架级依赖。

## 用户场景与测试

### 用户故事 1：逐项选择父类字段（P1）

管理员在类别编辑对话框中决定子类继承哪些字段，资产录入只出现最终有效字段。

**优先级原因**：这是本轮核心能力，必须同时保证选择状态、字段来源和真实资产行为一致。

**独立验收**：创建三层类别和多个字段，保存不同选择，再比较类别详情、资产表单与服务端写入校验。

1. 父类有效字段为 A、B，新建子类时，两项都是候选但默认不选；子类直接绑定的 C 不受影响。
2. 子类选择 A 并保存后，有效集为 A、C；B 不进入录入表单，也不能作为该子类编号字段。
3. 祖父直接绑定 A、B，父类只继承 A 并直接绑定 C，孙类只能选择 A、C，不能跳过父类选择 B。
4. 孙类继承 A 时，来源仍显示祖父这个原始绑定类别，不能显示为孙类或父类直接绑定。
5. 父类后来新增 D，只在子类候选中出现；子类及后代的已选集不变。
6. 草稿勾选不立即写入；取消对话框后，类别配置、继承选择和资产结果全部不变。
7. 类别自身直接绑定字段不出现在继承勾选区；管理直接绑定仍进入字段编辑器。

### 用户故事 2：升级不改变现有资产字段（P1）

管理员升级系统后，现有类别及资产仍看到原来的字段，无需手工重新勾选。

**优先级原因**：迁移错误会使已有资产的有效字段、编号和唯一性范围突然改变。

**独立验收**：在旧版本结构的真实临时数据库中建立多层类别、绑定和资产，运行迁移，对比迁移前后结果。

1. 含根、子、孙三级继承的数据库迁移后，每个类别的有效字段 ID、顺序、原始来源和字段规则与迁移前一致。
2. 迁移不改变直接绑定记录、不把继承类别加进字段的直接绑定列表，不改变资产 UUID、属性值、显示编号或流转记录。
3. 原有唯一字段仍使用原始绑定类别的范围；原有搜索和唯一精确匹配结果不因迁移改变。
4. 迁移完成后父类新增字段，现有子类也不会自动继承；没有额外的旧类别兼容模式。
5. 迁移失败时不留下部分回填的选择或半更新的结构；恢复策略不得把未完成迁移当作成功升级。

### 用户故事 3：安全撤回及重新启用继承（P1）

管理员取消一个字段时能看清后代影响，历史取值保留；恢复时不会静默覆盖数据。

**优先级原因**：这是最容易产生丢值、错误搜索和唯一性冲突的路径。

**独立验收**：使用有后代选择、资产取值、搜索索引和唯一索引的类别，分别执行撤回、取消确认、恢复和冲突恢复。

1. 父类取消继承 A，导致子类失去 A 来源时，保存前展示受影响后代类别及字段、资产影响数量；未确认不写入。
2. 确认后，各后代失效的选择一起撤回；原资产 A 值不删除，详情显示为只读归档属性。
3. 父类重新选择 A 后，子类不自动恢复，A 只重新成为子类候选。
4. 子类主动重新选择 A 后，合法的旧值恢复为有效属性，不要求重复录入。
5. 旧值不满足当前类型、格式、范围等规则，或恢复会产生唯一值冲突时，拒绝整次保存并定位字段和冲突资产。
6. 子类甲、乙继承同一来源的唯一字段且甲使用 ABC；甲撤回后释放此有效唯一值，乙可使用 ABC；甲再恢复时因冲突被拒，双方资产值均不被覆盖。
7. 撤回后不能通过该字段的普通搜索或唯一精确匹配命中撤回资产；若资产另有有效字段命中同一搜索词，仍可正常返回。
8. 预览后其他操作改变了相关类别、绑定或资产数据，提交必须重新校验；影响与已确认内容不一致时要求刷新确认，不扩大原确认的范围。

### 用户故事 4：在一次保存中处理依赖与类别移动（P1）

管理员可以一起调整父类别、继承字段和编号配置，但不能保存一个依赖缺失的有效字段集。

**优先级原因**：只更新继承表而不检查依赖，会让存量资产从下一次编辑起无法保存。

**独立验收**：覆盖编号引用、计算链、三级后代及允许移动和禁止移动的类别。

1. 当前编号字段 A 被取消时，同一类别编辑草稿必须更换或清空编号；未处理则拒绝保存。
2. 后代编号引用将失效，或任何仍有效的计算字段依赖将失效时，整次操作被拒，返回类别与字段原因，不自动清空后代编号或删除计算字段。
3. 计算字段 Z 依赖 A、B，只选 Z 的草稿提示缺少 A、B；不自动勾选，保存必须失败。
4. 在一次草稿中同时取消输入字段和所有依赖它的继承计算字段，且后代无残留依赖时，允许保存。
5. 对允许移动的类别，原选 A、B，新父类提供相同字段 ID 的 B 和新字段 C，草稿保留 B、撤回 A、默认不选 C；仅 key 相同但字段 ID 不同不算 B。
6. 移动影响后代时沿用撤回确认及依赖守卫；新父类别、选择、编号配置与派生数据要么一起成功，要么全部回滚。
7. 当前已禁止的类别移动仍被禁止，不能借继承配置绕过原有移动或树环守卫。
8. 即使子类不继承祖先的 code，也不能在该链上直接绑定另一个同 key 字段；兄弟类别原有同 key 规则不变。

### 用户故事 5：存量资产、计算与各功能口径一致（P1）

继承变更后，读取、录入、导入导出和索引立即按同一个有效字段集工作，不等待逐台编辑资产。

**优先级原因**：单独改类别界面会产生表单、索引和导出互相矛盾的状态。

**独立验收**：对同一批含不同型号、厂商的资产完成继承变更，逐项检查消费者结果和数据库对帐。

1. 已有资产没有新继承的必填采购日期，仍允许继承，不填入虚构值；新资产保存必须填写，已有资产下次编辑保存必须补齐。
2. 恢复非空归档值时检查其合法性；缺失值按上述必填规则处理，不能形成“未继承无法填、未填无法继承”的死锁。
3. 本次变更新增或恢复的计算字段，以及依赖本次变化而需更新的有效计算字段，必须为受影响资产成功求值并通过唯一性检查；任一失败整次回滚。
4. 成功后，详情、录入与编辑、编号候选、列表列解锁、导入模板、逐行导入校验、导出、rows 和打印均遵循新有效集。
5. 导入文件仍允许包含不同型号的设备字段，逐行按型号判定；类别继承变化不缩窄成单一型号模板。
6. 撤回字段不再作为该类别的有效导出或打印字段；保留在原始属性中的旧值不得泄漏成有效单元格。
7. 型号和厂商提供的字段不因类别继承取消而丢失，类别与设备绑定模式互斥仍成立。
8. 普通搜索索引、有效唯一索引与有效字段同步；对帐必须能发现继承变更后的漏项、残留和范围错误。

### 边界场景

- 根类别没有继承候选，只保留直接绑定；选择全部为空是合法状态。
- 直接父类没有有效字段时显示明确空态，不把加载失败当成空候选并覆盖原选择。
- 直接父类解绑字段与父类取消继承，都会使下游失去来源，必须通过同一传播与守卫规则。
- 原始字段定义删除仍沿用存量值与引用保护；有归档值不等于可直接删定义。
- 换父类后同一字段 ID 的原始绑定类别若改变，唯一范围必须按新来源重算并检查冲突，不能只保留旧 scope。
- 新选中必填字段允许存量缺值，不代表计算字段可保留旧的或无法计算的结果。
- 重复提交、取消确认、保存失败、并发修改都不能造成部分选择、部分索引或部分计算结果落库。
- 中文、英文、窄屏、键盘操作、无管理权限、长字段名和长来源路径均有明确可用状态。

## 功能需求

- **FR-001**：继承必须按字段 ID 显式选择，来源仅为直接父类当前有效字段；禁止跨层选择。
- **FR-002**：最终类别有效集必须由自身直接绑定与选中的父类有效字段组成，保留原始来源；字段规则不允许在继承层覆盖。
- **FR-003**：直接绑定与继承选择必须独立存储，字段列表的 category_ids 继续只表示直接绑定。
- **FR-004**：迁移回填现有选择，保持有效集、来源、字段顺序、属性和唯一范围不变；之后统一采用正向选择，无旧模式。
- **FR-005**：新建子类默认不继承；上游新字段默认不选；上游恢复不得自动复活已被撤回的后代选择。
- **FR-006**：失去来源的后代选择必须在确认后同步清除；存量取值保留为归档属性，不静默删除。
- **FR-007**：恢复选择必须启用合法旧值，检查现存值与唯一性；失败定位原因并整次回滚。
- **FR-008**：有效唯一范围必须继承原始绑定类别，只约束字段实际生效的资产；撤回即时释放，恢复或来源变化重新检查。
- **FR-009**：继承撤回释放的值不得继续通过遗留唯一索引记录参与普通搜索或唯一精确跳转；不得仅设置 archived_at 后任由历史索引查询继续命中。
- **FR-010**：编号字段必须属于最终有效类别字段；保留非唯一编号能力及 UUID 身份规则，设备侧字段不能作为类别编号字段。
- **FR-011**：计算字段依赖必须在最终有效字段集合内显式存在；校验当前类别及受影响后代，不自动勾选、不自动移除依赖者。
- **FR-012**：继续执行同一祖先链上的同 key 冲突、类别与设备侧绑定互斥及现有类别移动限制。
- **FR-013**：移动时按字段 ID 保留仍可选的选择，撤回失去来源的选择，新候选默认不选；所有来源与依赖必须重新解析。
- **FR-014**：首次继承必填字段不回溯强制补齐存量缺值；新建与下次编辑执行必填校验。恢复的非空值必须合法。
- **FR-015**：本次变化所需的存量计算必须成功，计算值及其唯一性冲突须阻止整体提交，不允许异步留下混合结果。
- **FR-016**：类别配置、当前及后代选择、唯一与搜索索引、计算结果必须原子更新；失败无部分写入。
- **FR-017**：影响预览只读；提交重新校验当前数据和已确认影响，过时确认不得授权新增加的破坏性影响。
- **FR-018**：类别编辑对话框提供继承勾选、字段类型、必填状态、原始来源；自身直接绑定不在勾选区，详情保持只读。
- **FR-019**：父类别、继承选择、编号及其他类别属性必须统一保存。清空选择与未修改选择必须能区分，避免普通元数据更新清空继承。
- **FR-020**：所有消费者必须采用共同的类别有效字段规则；单资产字段与混合型号可能字段集的区别保留，不各自重新拼祖先并集。
- **FR-021**：绑定、解绑、字段删除、计算引用、必填影响计数、类别字段过滤、重算和 verify 必须审查实际到达范围；不可将原 path 前缀假设继续当作有效继承。刻意保留的同链 key 守卫除外。
- **FR-022**：继承写操作沿用 schema.manage 服务端权限；无权限者可读，前端禁用并说明原因，不新增权限开关。
- **FR-023**：全部用户文案中英齐备；失败通过统一错误边界渲染，字段错误定位，冲突对象以 UUID 定位而非显示编号。
- **FR-024**：加载、空、失败、提交中状态明确；确认可取消；界面使用现有 shadcn/ui 体系并新增真实 DOM 交互测试。
- **FR-025**：端点变更必须同步两份全量 OpenAPI 合约与 deploy/smoke.sh，并有真实 SQLite 集成测试。

### 关键实体

- **类别**：保留父子关系与直接绑定，并拥有显式继承选择。
- **继承选择**：类别选择一个来自直接父类有效集的字段；不是直接绑定，也不是字段值的副本。
- **有效字段**：字段定义、原始绑定来源、继承标记及稳定顺序的解析结果。
- **变更影响**：本次新增、撤回、来源变化涉及的类别与字段、资产数量、阻塞依赖和数据冲突，用于预览及提交重校验。
- **资产属性与派生索引**：旧值保留；是否有效取决于解析结果，索引与计算结果随成功事务同步。

## 可衡量的验收结果

- **SC-001**：旧库迁移测试中所有类别迁移前后的有效字段 ID、顺序、来源、规则和唯一范围逐项相等；资产属性和流转记录零损失。
- **SC-002**：三层继承矩阵中，未选择、新增上游、撤回及恢复均无非预期字段传播；重复读取结果一致。
- **SC-003**：所有阻塞场景，包括编号依赖、计算缺项、旧值非法、唯一冲突和过时预览，失败前后类别配置、选择、资产值及派生索引保持一致。
- **SC-004**：撤回后无残留字段索引命中；恢复后无需逐台编辑即可正确搜索，并能检测跨子类唯一冲突。
- **SC-005**：同一测试数据在类别详情、资产表单、列表列、模板、导入校验、导出、rows 和打印中满足同一有效性规则，型号与厂商回归全部通过。
- **SC-006**：新增每条用户可见交互路径均有 DOM 测试，新增或修改端点均有真实 SQLite 集成测试，核心管线覆盖率不低于 80%。
- **SC-007**：实现交付前七条合并门禁实际通过；生产构建及性能要求沿用章程，禁止用本轮规格默许 N+1 或无上限列表。

## 已确认的设计边界

### 存储与解析

保留 category_fields；新增独立的正向继承选择表，逻辑唯一键为类别 ID 与字段 ID。父类别由类别树确定，原始来源由解析得到，不依靠复制绑定或手工维护第二份来源事实。

解析沿根到当前类别逐层执行：取该层明确选中的上一层有效字段，再加入该层直接绑定。继承字段维持父层顺序，自身字段维持现有绑定排序；迁移前后顺序保持一致。本轮不新增继承字段单独排序功能。

来源不合法的选择必须在写事务中拒绝或按已确认的向下撤回流程清理，不能留作将来自动恢复的潜伏选择。

### 写入与一致性

类别变更由领域层统一计算影响；HTTP 层只负责输入输出与错误渲染。预览和提交复用规则；写事务使用 BEGIN IMMEDIATE、单写连接，提交在事务内重新读取并校验。

既有绑定、解绑入口不能绕过传播服务。特别是字段编辑器中撤销祖先直接绑定，同样要先说明后代影响、检查依赖并同步撤回。不能只给类别编辑入口加保护。

正常成功路径必须同步更新索引及本次需要的计算结果，不等待资产下次编辑。与继承无关的计算规则和流转状态不借机修改。元数据变化不伪造资产持有方、负责人或状态流转事件；沿用现有审计记录方式。

### 接口边界

类别有效 schema 仍用于读取最终字段；编辑还需要直接父类可选字段及已选状态，不能把未选候选混进 fields 让表单误渲染。类别创建、编辑支持完整选择集合，省略表示未提出选择修改，空集合表示明确清空；创建时省略即默认空。

需要只读影响预览与最终一次保存的能力；具体路由、响应字段、确认凭据及并发校验方式在实现计划和合约中落实，不通过前端连续调用多个写端点模拟原子操作。

## 与现行规则的关系

| 现行规则 | 本轮处理 |
|---|---|
| 类别沿祖先链自动继承全部字段 | 改为逐层、逐字段正向选择；迁移只保留当时结果 |
| 类别对话框不管理字段绑定 | 保留直接绑定管理边界；新增的是继承选择，不是直接绑定 |
| 编号候选为类别链字段 | 收窄为最终有效类别字段；仅存在于祖先绑定但未继承的不再合法 |
| 唯一性属于原始绑定类别子树 | 保留来源范围，但只覆盖实际继承生效的资产 |
| 唯一搜索可命中历史归档编号 | 对“继承撤回导致失效”的值作明确例外：不再命中，不再形成精确跳转；其他既有历史编号行为不在本轮整体推翻 |
| 必填只在下次写入要求补齐 | 保留；已有非空值恢复及本次计算结果必须通过校验 |
| 有效集可以靠 path 前缀推定 | 改为真实选择到达；同链 key 冲突保守限制刻意保留 |
| 厂商字段实时传播至型号 | 不变 |

实施时同步更新 docs/rules/schema.md 及涉及的领域、表单规则，明确替代条款；本规格完成不表示现有业务代码已经实现这些规则。
