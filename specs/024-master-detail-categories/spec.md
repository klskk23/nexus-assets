# 规格：类别页改主从两栏，并抽出主从骨架

**分支**：`024-master-detail-categories` ｜ **决策**：151–160
**推翻**：014 决策 90/92 对类别页的适用（「类别页也套用 `CrudPage` 约定」）、
类别树的展开/折叠

## 概要

类别是一棵树，今天被塞进了一张表。

**这不是当初写错了。** 014 把类别页收进 `CrudPage` 是有理由的：那一轮的任务是
「表格页的零件只有一套」，而类别页当时确实只需要一张能搜、能点行的列表。缩进 +
深度优先顺序把树压进表格，是那个约束下的正确解。

变的是问题。类别现在承载的东西比那时多：它决定一台设备记录哪些字段、能打哪些标签、
编号从哪个字段来，而这些**只有点开对话框才看得见**。于是「这个类别到底配了什么」
这个问题，每问一次就要开一次对话框、关一次对话框，再开下一个 —— 而人真正想做的是
**在几个类别之间来回比**。对话框天生做不到这件事：它一次只能开一个，且开着的时候
背后那棵树是 `aria-hidden` 的。

所以类别页要变成**左边一棵常展开的树，右边是选中那一个的全部配置**。切换类别是点一下，
不是开关一次对话框。

### 为什么同一轮要抽骨架

开发者已经说明：**后续其他页也可能脱离 `CrudPage` 变成同样的形状。**

所以本轮不能把两栏写成类别页的一次性布局。但也**不能重演 `CrudPage` 的教训** ——
`web-tables.md` 里那句话是这个仓库自己付过学费的：「不要把手写的三个塞进 `CrudPage`，
它会长出『没有新建按钮』『勾选列』『树』三个特例开关」。

一个只有一个调用方的抽象，最容易犯的错是**把今天这一个调用方的每一个细节都变成参数**。
本轮的判据写死在下面 FR-016：**骨架只拿「页面的形状」，不拿「这一页的内容」**，
且以「第二个调用方进来时不必改骨架」为验收标准，而不是「参数开得够多」。

### 计数是这一轮唯一会让人以为数据错了的地方

树上每个节点要显示设备数。系统里今天已经有一处在回答同一个问题 —— 概览的类别分布。
它的口径是**含子类别、不含标了「不计入类别分布」的状态**（目前只有已报废），
且只滚到根类别。

**同一个系统里不能有两种「这类有多少台」。** 一个类别在概览显示 40、在类别页显示 43，
没有任何界面能解释这个差，而看到的人会认为账错了 —— 那比缺这个数字更糟。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一眼看清一个类别配了什么，并能在类别之间来回比（Priority: P1）

管理员打开类别页，左边是完整展开的类别树，点任意一个节点，右边立刻显示它的
上级、代号、编号字段、可打印的标签，以及这个类别的全部字段（含从祖先继承来的）。
点下一个节点，右边整块换掉。

**为什么是 P1**：这是本轮的动因。今天这件事要开关对话框才能做，而人要做的是比较。

**独立测试**：造一棵至少两层的类别树，逐个点选，右边内容随之更换且正确。

**验收场景**

1. **Given** 存在多层类别，**When** 打开 `/categories`，**Then** 树完整展开，没有任何展开/折叠控件
2. **Given** 在类别页，**When** 点击树上某个节点，**Then** 右栏显示该类别的上级类别、代号、编号字段、可打印的标签
3. **Given** 选中一个子类别，**When** 查看右栏的字段表，**Then** 本类别自己绑的字段与继承自祖先的字段都在，继承来的标出**继承自哪个类别**
4. **Given** 选中一个类别，**When** 查看右栏，**Then** 有一条通往该类别设备列表的入口，且该入口**含子类别**
5. **Given** 右栏正在显示某类别，**When** 查看字段表，**Then** 每行**没有**解绑按钮，也没有拖拽手柄，并有一句话说明绑定在哪里做

### User Story 2 - 树上的数字与概览一致（Priority: P1）

树上每个节点后面显示该类别（含子类别）的设备数，与概览类别分布对同一个类别给出
**同一个数**。

**为什么是 P1**：这是唯一一处做错会让人认为**数据本身错了**的地方。其余各项做错
只是难看或难用。

**独立测试**：同一份数据下，读概览某根类别的数与类别页同一节点的数，必须相等；
改一台设备的状态为「不计入类别分布」的状态，两处必须同时变化。

**验收场景**

1. **Given** 某根类别在概览显示 N，**When** 在类别页看同一个类别，**Then** 也显示 N
2. **Given** 某类别有子类别，**When** 看它的数，**Then** 它是整棵子树的合计（父节点自己直挂的 + 全部后代的）
3. **Given** 一台设备处于标了「不计入类别分布」的状态，**When** 看两处的数，**Then** 两处都不把它算进去
4. **Given** 某个类别下一台设备也没有，**When** 看树，**Then** 显示 0，而不是空白（空白会读作「没查到」）

### User Story 3 - 有权限的人能改，没权限的人知道有这回事（Priority: P2）

有 `schema.manage` 的人点右栏的「修改」，在对话框里改名称、上级、编号字段、
可打印的标签，保存后左右两栏立刻反映。没有该权限的人看得到整页内容，
「修改」按钮禁用并说明缺什么。

**为什么是 P2**：编辑能力今天已经有且能用，本轮只是换了入口位置。

**独立测试**：分别以有权限与无权限的身份打开同一个类别，比较按钮状态与提示。

**验收场景**

1. **Given** 有 `schema.manage`，**When** 点「修改」，**Then** 打开编辑对话框，一次保存名称/上级/编号字段/可打印的标签
2. **Given** 在对话框里改了名称并保存，**When** 对话框关闭，**Then** 左栏该节点的名字与右栏标题同时更新
3. **Given** 在对话框里改了上级并保存，**When** 对话框关闭，**Then** 该节点在树上移动到新位置，且仍处于选中态
4. **Given** 没有 `schema.manage`，**When** 打开类别页，**Then** 全部内容可见，「修改」按钮禁用且悬停说明需要哪个权限
5. **Given** 没有 `schema.manage`，**When** 查看左栏底部，**Then** 「新建类别」同样禁用并说明
6. **Given** 要删除一个类别，**When** 寻找删除入口，**Then** 它在编辑对话框里，右栏上没有破坏性按钮

### User Story 4 - 选中能被分享、刷新、后退（Priority: P2）

选中的类别写进地址。把地址发给同事，他打开看到同一个类别；刷新不丢；
浏览器后退回到上一个看过的类别。

**为什么是 P2**：不做也能用，但这个产品已有的习惯是「选中与筛选都写地址」，
类别页是最后一个还没这么做的地方。

**独立测试**：选中若干类别，逐个复制地址、新开页面打开、刷新、后退。

**验收场景**

1. **Given** 点击某类别，**When** 查看地址栏，**Then** 地址包含该类别的标识
2. **Given** 复制该地址，**When** 在新会话打开，**Then** 直接选中并显示该类别
3. **Given** 首次打开类别页且未指定类别，**When** 页面加载完成，**Then** 默认显示第一个根类别，**地址保持 `/categories`**（见 FR-021 的修订理由）
4. **Given** 依次看过三个类别，**When** 连按后退，**Then** 逐个回退到先前看过的类别
5. **Given** 地址里的类别标识不存在（已被删除或拼错），**When** 打开，**Then** 说明找不到该类别并给出回到类别页的去处，而不是白屏

### User Story 5 - 类别多起来之后还能找到（Priority: P3）

类别长到几十个时，左栏顶部的搜索按名称与代号收窄；一开始搜索，左栏从树切成平展的
命中列表，每行显示完整路径。

**为什么是 P3**：类别少时用不上；但一旦长起来，没有它左栏就是一根长滚动条。

**独立测试**：造二十个以上分布在多层的类别，搜索一个只在深层出现的词。

**验收场景**

1. **Given** 树上有多层类别，**When** 在搜索框输入，**Then** 左栏切成平展的命中列表，不再有缩进
2. **Given** 处于搜索结果中，**When** 看某个深层命中项，**Then** 它显示完整路径（如「网络设备 / SDWAN 路由器」）
3. **Given** 处于搜索结果中，**When** 清空搜索框，**Then** 左栏恢复成完整展开的树
4. **Given** 搜索无命中，**When** 查看左栏，**Then** 说明没有匹配，而不是一片空白
5. **Given** 处于搜索结果中，**When** 点击某个命中项，**Then** 右栏显示它，行为与在树上点击一致

### Edge Cases

- **一个类别都没有**：左栏显示空状态并指向「新建类别」，右栏不画半页空白的详情框架。
- **只有一个类别**：自动选中它；树只有一行，仍然不画展开/折叠控件。
- **地址里的类别刚被别人删掉**：见 US4 场景 5。
- **删掉的正是当前选中的那个**：删除后选中落到哪里必须是确定的，不能停留在一个已经不存在的类别上。
- **改上级把类别移走**：选中不丢（US3 场景 3）。
- **类别名很长**：左栏一行放不下时截断并可读出全名，不能把左栏撑宽。
- **树很深**：缩进不能把深层节点的名字挤没。
- **窄屏**：两栏塌成一栏。
- **打印服务离线**：可打印的标签沿用现有的离线表述，不因为换了布局而变成空白或报错。
- **没有编号字段**：显示「未设置」的既有表述，不是空白。
- **字段一个都没绑**：右栏字段区说明没有字段，并指向去哪里绑。

## Requirements *(mandatory)*

### Functional Requirements

**页面形状**

- **FR-001**：类别页 MUST 是左右两栏：左为类别层级，右为当前选中类别的详情。
- **FR-002**：左栏的树 MUST 始终完整展开。展开/折叠控件与相应的右键菜单项 MUST 移除。
- **FR-003**：左栏 MUST 在顶部提供搜索，按名称与代号匹配；有搜索词时 MUST 从树切成平展命中列表，每行显示完整路径；清空后 MUST 恢复成树。
- **FR-004**：左栏底部 MUST 有「新建类别」入口（不是「新建子类别」），上级在表单中选择。
- **FR-005**：左栏每个节点 MUST 显示该类别的设备数。

**计数口径**

- **FR-006**：节点上的设备数 MUST 是**整棵子树的合计**，且 MUST 与概览类别分布采用同一口径 —— 含子类别、排除标记为「不计入类别分布」的状态。
- **FR-007**：概览与类别页对同一个类别 MUST 给出同一个数。这条 MUST 由测试固定，且该测试 MUST 同时读两条路径的结果做比较，而不是各自与常量比。
- **FR-008**：设备数为零 MUST 显示 0，不得显示空白。

**右栏内容**

- **FR-009**：右栏 MUST 显示所选类别的上级类别、代号、编号字段、可打印的标签。上级类别 MUST 只作为名字显示，不可点击。
- **FR-010**：右栏 MUST 列出该类别的**字段**（而非字段组），包含继承自祖先类别的字段，并标出继承自哪一个。字段组 MUST NOT 出现在这一栏。
- **FR-011**：右栏的字段区 MUST 只读 —— 没有解绑控件、没有排序控件，并 MUST 保留指向字段页的既有说明文案。
- **FR-012**：右栏 MUST 提供一条通往该类别设备列表的入口，且 MUST 含子类别，与概览类别分布的跳转口径一致。
- **FR-013**：右栏 MUST NOT 包含删除或其他破坏性动作。

**编辑与权限**

- **FR-014**：右栏 MUST 有「修改」入口，打开现有的类别编辑对话框；名称、上级、编号字段、可打印的标签 MUST 在一次保存中提交。删除 MUST 留在该对话框内。
- **FR-015**：无 `schema.manage` 的使用者 MUST 能看到本页全部内容；「修改」与「新建类别」MUST 禁用并说明缺少哪个权限，MUST NOT 隐藏。

**骨架与调用页的分界**

- **FR-016**：主从两栏 MUST 抽成可复用的骨架。骨架**只**负责**页面的形状**：两栏栅格、左栏的滚动与选中态、从地址解析当前选中、未指定时默认第一项、窄屏塌成一栏。**两栏的空状态属于调用页**（见 FR-017）。
- **FR-017**：以下 MUST 属于调用页而非骨架：左栏每一行长什么样、左栏的数据从哪来与如何排序、右栏的全部内容、左栏底部有没有按钮及其行为、搜索的匹配规则。
- **FR-018**：骨架 MUST NOT 出现「是不是树」「有没有计数」「有没有底部按钮」这类针对类别页的开关。验收标准是**第二个调用方接入时不需要修改骨架**，而不是参数数量。
- **FR-019**：本轮 MUST 只有类别页一个调用方。MUST NOT 为了「将来可能用到」预先增加骨架的能力。

**导航**

- **FR-020**：选中的类别 MUST 写进地址，且 MUST 支持刷新、粘贴地址打开、浏览器前进后退。
- **FR-021**：未指定类别进入本页时 MUST 默认显示第一个根类别。
  **地址 MUST 保持不带 id** —— 原本要求把地址改写成 `/categories/:id`，实机走查证明
  那会让窄屏的树**永远不可达**：窄屏两栏是两页，不带 id 的地址就是列表页，
  从它跳走等于每一个入口都落在详情上。改写地址换来的只是「地址更精确」，
  代价是手机上整棵树消失。
- **FR-022**：地址指向不存在的类别时 MUST 给出说明与去处，MUST NOT 白屏或静默回落。
- **FR-023**：窄屏 MUST 塌成一栏：先看树，选中后看详情。详情上 MUST 有一个**窄屏可见的返回入口**指向列表地址，使它与浏览器后退指向同一处而不是互相竞争。
- **FR-024**：删除当前选中的类别后，选中 MUST 落到一个确定且存在的类别（或本页的空状态）。

**范围之外**

- **FR-025**：本轮 MUST NOT 引入类别停用/归档。
- **FR-026**：本轮 MUST NOT 改动字段绑定模型、字段组语义、或类别编辑表单的字段构成。

**文档**

- **FR-027**：`web-tables.md` 中「类别页也套用了 `CrudPage` 约定」一段 MUST 改写，并 MUST 写明这次为什么反过来 —— 不是「当初错了」，而是类别承载的信息变了。
- **FR-028**：骨架与调用页的分界 MUST 写进 `docs/rules/`，供第二个调用方参照。

### Key Entities

- **类别**：名称、代号、上级、编号字段、可打印的标签。层级关系决定字段继承。本轮不新增属性。
- **类别设备计数**：某类别子树下、处于「计入类别分布」状态的设备数量。本轮新增的读取路径，与概览共用口径。
- **主从骨架**：一个页面形状 —— 一栏可选列表 + 一栏当前项详情 + 选中写地址。不含任何一页的内容。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：查看三个类别各自配了哪些字段，全程**零次**打开与关闭对话框。今天这个数是 3 开 3 关。
- **SC-002**：概览与类别页对同一个类别显示的设备数，在任意数据下**完全相等**（由比较两条路径结果的测试固定，而非各自比常量）。
- **SC-003**：从打开类别页到看清任一类别的完整配置，**只需一次点击**（默认已显示第一个根类别）。
- **SC-004**：把当前所看类别的地址发给同事，他打开后看到**同一个类别**，无需任何口头说明。
- **SC-005**：第二个页面改用主从骨架时，骨架文件**零改动** —— 本轮以「骨架不含任何类别专有概念」为该目标的可检验替身。
- **SC-006**：无 `schema.manage` 的使用者能看到本页 **100%** 的信息，且能从界面上得知自己缺少哪个权限。
- **SC-007**：类别数量增长到二十个以上时，找到任意一个类别仍**只需一次搜索输入**，不需要滚动浏览。

## Assumptions

- **类别数量在一屏到几十之间。** 左栏常展开的前提是树不会长到需要分页；类别是配置而非数据，这个假设与「类别页不翻页」（014 决策 91）一致。若某天类别真的上百，需要的是重新审视这个假设，而不是加回折叠。
- **计数不需要实时精确到秒。** 与概览同源即可，两处都在页面加载时取数。
- **「第一个根类别」的顺序** 沿用类别列表现有的返回顺序，本轮不重新定义排序。
- **窄屏是次要场景。** 内网台账主要在桌面使用；窄屏要求是「不坏」，不是「同样好用」。
- **打印标签仍由外部打印服务定义**，本轮只是换个地方显示既有信息。
