# Feature Specification: 编号模型重构与流转补全

**Feature Branch**: `001-asset-ledger-demo`（本特性直接在该分支上实现，未另开分支）

**Created**: 2026-08-28

**Status**: Implemented

**Input**: User description: "1. 类别不需要强制绑定编号生成规则，资产的最终唯一内部编号就是 UUID。
把编号生成规则这个功能归到信息项里面。信息项分为静态键和表达式键，表达式键依赖静态键表达式生成，
类别可以绑定表达式键，但是如果表达式键的依赖不存在则拒绝绑定。
2. 当前资产流转系统功能不完善，资产首次录入后无法在持有方之间进行流转，也无法更改状态，需要增加按钮。
3. 资产/类别实际上没有绑定设备型号。持有方默认库存点无法更改和设置。"

> 数据库标识符。用户可见文案（UI 文本、字段 label、`error.message`）使用中文。

| 001 的需求 | 本规格的处置 |
|------------|--------------|
| FR-008 编号由类别规则自动生成 | **取代** → FR-001、FR-002：编号是一个信息项，类别只选用哪一个 |
| FR-012、FR-013 编号变更后旧编号保留为别名 | **推广** → FR-011、FR-012：任何唯一信息项的旧值都保留 |
| FR-031 被编号规则或计算项引用的信息项不得停用 | **推广** → FR-018：新增「被某类别选作显示编号」这一种引用 |
| FR-035、FR-036 重算存量编号 | **推广** → FR-021、FR-022：重算对象从编号扩大到全部表达式键 |
| FR-046 精确匹配编号、历史编号与 MAC | **取代** → FR-013：精确匹配任一唯一信息项 |
| FR-017 删除资产需输入资产编号确认 | **调整** → FR-006：输入的是显示编号，未配置时为 UUID 短码 |
| FR-045 默认库存点 | **收紧** → FR-029、FR-030：只能更换，不能取消 |
| FR-030 型号可提供默认值 | **补全** → FR-026 ~ FR-028：界面上从来没有型号选择器 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新类别不再被编号规则挡住 (Priority: P1)

管理员新建一个设备类别、绑好要记录的信息项，直接录入第一台设备。他不需要先想清楚这类设备的
编号怎么编 —— 那是可以以后再决定的事，甚至可以永远不决定。

**Why this priority**: 这是用户报告的第一个痛点，也是唯一一个会让人**完全无法工作**的问题。
在此之前，一个没配编号规则的类别是死的：任何资产都存不进去，错误提示还指向一个用户根本
没打算配置的东西。修掉它，其余四个故事才有讨论的余地。

**Independent Test**: 用一个空系统，新建一个类别、绑定一个文本信息项，不做任何编号相关配置，
录入一台设备。设备保存成功，列表与详情页都能指代它。全程不触及表达式键、流转、型号。

**Acceptance Scenarios**:

1. **Given** 一个没有配置显示编号的类别，
   **When** 录入一台设备，
   **Then** 保存成功，不出现任何与编号有关的错误
2. **Given** 上述设备已保存，
   **When** 查看资产列表，
   **Then** 首列显示该设备 UUID 的前 8 位十六进制，可点击进入详情
3. **Given** 上述设备，
   **When** 在搜索框输入它的 UUID，
   **Then** 直接进入该设备的详情页
4. **Given** 上述设备，
   **When** 执行删除，
   **Then** 二次确认要求逐字输入界面上显示的那个 8 位短码，输错则拒绝

### User Story 2 - 编号是一个信息项 (Priority: P2)

管理员想让这类设备有一个人能念出来的编号。他在信息项库里建一个表达式键，模板写
`{{ .attrs.mac | hex2dec }}`，标为唯一，绑到类别上，再在类别的「显示编号」里选中它。
此后这类设备的列表首列、导出首列、删除确认都用它。

**Why this priority**: US1 让系统不再卡死，但仓库同事仍然需要一个能贴在标签上、能在电话里
念出来的编号。这个故事把编号能力还回来 —— 区别在于它现在是可选的、可以有多套、
且和其他推导字段没有任何机制上的差异。

**Independent Test**: 在 US1 的类别上补一个 MAC 信息项与一个读它的表达式键，设为显示编号，
录入设备后确认编号被推导出来；改一次 MAC，确认编号跟着变、旧编号仍能搜到。

**Acceptance Scenarios**:

1. **Given** 一个标为唯一的表达式键已绑定到类别，
   **When** 在类别的「显示编号」下拉中选择它并保存，
   **Then** 该类别下所有设备改用它的取值作为编号
2. **Given** 「显示编号」下拉，
   **When** 展开它，
   **Then** 只列出该类别有效字段集中标为唯一的信息项；未标唯一的不出现在选项里
3. **Given** 一个未标为唯一的信息项，
   **When** 通过接口强行把它设为显示编号，
   **Then** 系统拒绝，并说明必须先把该信息项标为唯一
4. **Given** 某台设备的 MAC 被修正，
   **When** 保存，
   **Then** 由它推导的编号随之改变，旧编号与旧 MAC 都被归档
5. **Given** 上述归档的旧编号，
   **When** 用它搜索，
   **Then** 仍能定位到该设备
6. **Given** 上述归档的旧 MAC，
   **When** 用它搜索，
   **Then** 同样能定位到该设备
7. **Given** 一台设备的 MAC 写作 `AA:BB:CC:DD:EE:FF`，
   **When** 扫码枪输入 `aa-bb-cc-dd-ee-ff`，
   **Then** 直接进入该设备详情页
8. **Given** 某个唯一信息项的旧值已归档，
   **When** 另一台设备启用同一个值（如换主板后旧 MAC 转移到别处），
   **Then** 允许保存；此后用该值搜索命中多台，退化为列表而不直接跳转

### User Story 3 - 配置错误在配置时就被拦住 (Priority: P3)

管理员把一个读 `attrs.mac` 的表达式键绑到某个类别上。如果这个类别还没绑 `mac`，
或者绑了但没标必填，系统当场拒绝，并告诉他要先去改哪几项 —— 而不是等到某天有人
录不进设备时才发现。

**Why this priority**: US2 让表达式键可用，但也把一类新的错误引进了系统：一个求不出值的
表达式键会让整个类别的资产都存不进去，而错误信息指向的是表达式键，不是真正缺值的那个字段。
这个故事把发现时机从「录入时」提前到「配置时」，把错误对象从「结果」换成「原因」。

**Independent Test**: 建两个信息项 —— 一个静态键、一个读它的表达式键 —— 然后按错误顺序绑定，
确认每一步的拒绝理由都指向要先修的那一项；按正确顺序绑定则成功。

**Acceptance Scenarios**:

1. **Given** 一个表达式键读取 `attrs.rack`，而信息项库中没有 `rack`，
   **When** 把它绑定到某个类别，
   **Then** 系统拒绝，说明 `rack` 在信息项库中不存在
2. **Given** `rack` 已存在但尚未绑定到该类别，
   **When** 绑定表达式键，
   **Then** 系统拒绝，说明 `rack` 尚未绑定到该类别
3. **Given** `rack` 已绑定但标为选填，
   **When** 绑定表达式键，
   **Then** 系统拒绝，说明需要先把 `rack` 标为必填
4. **Given** `rack` 已绑定且必填，
   **When** 绑定表达式键，
   **Then** 绑定成功
5. **Given** 表达式键 A 读表达式键 B，B 读静态键 C，
   **When** 绑定 A 时 C 尚未满足条件，
   **Then** 系统拒绝并指出 C —— 依赖链被完整展开，不止查一层
6. **Given** 两个表达式键互相引用，
   **When** 把其中一个绑定到类别，
   **Then** 系统拒绝并给出循环路径
7. **Given** 某个类别上已绑定一个读 `mac` 的表达式键，
   **When** 尝试把 `mac` 从该类别解绑，
   **Then** 系统拒绝，并指出是哪个表达式键在读它
8. **Given** 某个信息项被某类别选作显示编号，
   **When** 尝试把它解绑或停用，
   **Then** 系统拒绝，并指出是哪个类别在用它
9. **Given** 一个已绑定的表达式键，
   **When** 把它的模板改成读取一个选填字段，
   **Then** 系统拒绝，并指出会因此失效的类别 —— 门禁不因绑定已完成而失效

### User Story 4 - 在详情页完成一次交接 (Priority: P4)

同事来借一台设备。经手人打开这台设备的详情页，点「流转」，选签出、选人、写一句备注，
提交。设备状态与持有方当场更新，时间线上多出一条记录。

**Why this priority**: 这是用户报告的第二个痛点。原先流转只存在于列表页的多选动作条 ——
要给一台设备做交接，得先回到列表、找到它、勾上、再操作。详情页是人看设备时所在的地方，
交接按钮不在那里，等于这个功能对单台设备不存在。

**Independent Test**: 打开任意一台设备的详情页，完成一次签出、一次改状态，
确认状态、持有方与时间线同步更新，全程不离开详情页。

**Acceptance Scenarios**:

1. **Given** 一台在库设备的详情页，
   **When** 点「流转」，
   **Then** 打开一个弹层，可选择签出/归还/转移/改负责人/改状态五种操作
2. **Given** 上述弹层，
   **When** 选择签出、指定目标账号并提交，
   **Then** 设备状态变为已签出、持有方变为该账号，时间线新增一条 `checkout` 记录
3. **Given** 上述弹层，
   **When** 选择改状态为维修中并提交，
   **Then** 状态更新，时间线新增一条 `status_change` 记录
4. **Given** 单台设备的流转，
   **When** 提交，
   **Then** 不产生批次标识 —— 单台不是一个批次
5. **Given** 资产列表页勾选了若干设备，
   **When** 点动作条上的「签出」，
   **Then** 打开与详情页同一个弹层，且操作已预选为签出
6. **Given** 状态机不允许的转换（如已报废设备改为已签出），
   **When** 提交，
   **Then** 系统拒绝并说明原因

### User Story 5 - 型号与默认库存点 (Priority: P5)

录入设备时选一个型号，该型号预设的信息项默认值自动填进尚未填写的字段。给某台已有设备
换型号时，系统列出会被覆盖的值，由经手人决定是否套用。

管理员把默认库存点从一个仓库换到另一个仓库。他改不掉的是「没有默认库存点」这个状态 ——
一旦设过，就只能换，不能取消。

**Why this priority**: 这是用户报告的第三、第四个痛点。型号功能的数据层早已存在，
但界面上从来没有过选择器，因此型号默认值这条能力**从未被触发过一次**。
默认库存点的问题是一个静默失败：接口接受了取消请求、什么也没做、返回成功。

**Independent Test**: 建一个带默认值的型号，录入设备时选中它，确认默认值被填入；
给一台已有设备换型号，确认弹出覆盖确认。分别尝试更换与取消默认库存点。

**Acceptance Scenarios**:

1. **Given** 一个带 `attr_defaults` 的型号，
   **When** 在录入页选中它，
   **Then** 尚未填写的字段被填入默认值，已经填过的保持不变
2. **Given** 型号下拉，
   **When** 展开它，
   **Then** 只列出属于该资产类别及其祖先链的型号，且不含已停用的
3. **Given** 一台已有设备，
   **When** 在详情页更换型号且新型号的默认值与当前值不同，
   **Then** 弹出确认，逐键列出 `当前值 → 新默认值`
4. **Given** 上述确认弹层，
   **When** 选择「仅换型号，保留现值」，
   **Then** 型号变更，所有信息项取值不变
5. **Given** 已有一个默认库存点，
   **When** 把另一个位置设为默认，
   **Then** 标记转移，原位置不再是默认
6. **Given** 已有一个默认库存点，
   **When** 尝试取消它，
   **Then** 系统拒绝并说明只能更换
7. **Given** 某个位置是当前默认库存点，
   **When** 尝试停用它，
   **Then** 系统拒绝，要求先把默认库存点转移到别处

### Edge Cases

- **类别没配显示编号，且 UUID 短码在视觉上难以区分**：8 位十六进制在同一屏内重复的概率
  可以忽略，但它对人不友好。这是「不配置」的自然代价，界面不做额外补偿
- **子类别没有继承父类别的显示编号**：这是有意的（决策 27）。子类别通常正是需要不同编号
  规则的地方，静默继承会给出意料之外的结果
- **表达式键求值失败**：仍然阻止整次保存（沿用 001 的 FR-029）。配合 FR-016 的必填强制，
  这条的触发面被压到最小
- **改一个已绑定的表达式键模板**：绑定时的依赖门禁只在绑定那一刻跑过，模板事后被改写是
  绕过它的路径（FR-020）
- **唯一值的旧值被另一台设备占用**：允许，且精确匹配因此可能命中多台（US2 场景 8）
- **导入文件内部的唯一值重复**：仍由「预览跑真实管线再回滚」覆盖，唯一性改由数据库约束
  兜底后行为不变
- **`asset_unique_values` 与 `attrs` 漂移**：任何绕过保存管线直接写 `assets` 的代码路径
  都会造成，由 `nexus verify` 双向对帐发现（FR-023）
- **解绑端点尚未开放**：`Unbind` 的守卫已实现，但 HTTP 层没有对应端点，界面上也只能绑不能解。
  这是 001 遗留的状态，本特性未改变

## Requirements *(mandatory)*

### Functional Requirements

**编号与标识**

- **FR-001**: 资产的唯一内部标识必须是 UUID；系统不得再维护独立的编号列
- **FR-002**: 编号生成规则必须作为一个普通信息项存在，与其他推导字段没有机制上的差异
- **FR-003**: 类别必须能指定其有效字段集中的某一个信息项作为「显示编号」，也必须允许不指定
- **FR-004**: 被指定为显示编号的信息项必须标为唯一；否则拒绝该指定并说明原因
- **FR-005**: 类别未指定显示编号时，界面与导出必须以该资产 UUID 的前 8 位十六进制指代它
- **FR-006**: 删除资产的二次确认必须要求逐字输入该资产当前显示的编号
- **FR-007**: 显示编号不得沿类别祖先链继承；子类别未指定即按 FR-005 回退

**信息项的两种形态**

- **FR-008**: 信息项必须在概念与界面上分为静态键与表达式键两组；数据模型不因此新增维度
- **FR-009**: 静态键的值由人工录入或导入产生；表达式键的值由模板对同一资产的其他键求值得到
- **FR-010**: 表达式键必须能引用其他表达式键，求值按依赖拓扑序进行

**唯一值与检索**

- **FR-011**: 系统必须为每个标为唯一的信息项维护当前值，并在数据库层面保证其唯一
- **FR-012**: 唯一信息项的值发生变化时，旧值必须被归档；归档值仍可被搜索命中，但不再占用唯一性
- **FR-013**: 精确匹配必须依次尝试：任一唯一信息项的当前值、任一唯一信息项的历史值、资产 UUID
- **FR-014**: 精确匹配命中唯一一条时直接进入该设备详情；命中多条时退化为列表
- **FR-015**: 精确匹配前必须对输入做与录入相同的规范化，使 `AA:BB:CC` 与 `aa-bb-cc` 命中同一台设备

**绑定护栏**

- **FR-016**: 把表达式键绑定到类别时，必须递归展开其依赖链；链上每一项都必须已在该类别的
  有效字段集内，且其中的静态键必须已标为必填。任一条不满足即拒绝绑定
- **FR-017**: 绑定被拒绝时，错误必须列出具体是哪些 key 缺失、哪些需要改为必填
- **FR-018**: 被表达式键读取、或被某类别选作显示编号的信息项，不得从该类别解绑，也不得停用
- **FR-019**: 表达式键之间形成循环依赖时，必须在绑定那一刻被拒绝，并给出循环路径
- **FR-020**: 修改一个已绑定的表达式键模板时，必须对它所绑定的每一个类别重新执行 FR-016 的检查

**重算**

- **FR-021**: 对某个类别子树重算表达式键必须是一个独立的、先预览后执行的操作
- **FR-022**: 重算若在任一唯一信息项上产生冲突，必须整体放弃，并输出完整的冲突清单

**对帐**

- **FR-023**: 唯一值的派生数据必须可与资产的实际取值双向对帐：既检出索引中有而取值已变的行，
  也检出取值存在而索引中缺失的行

**流转入口**

- **FR-024**: 资产详情页必须提供流转入口，可完成签出、归还、转移、改负责人与改状态
- **FR-025**: 详情页与列表页的流转必须使用同一个交互形态；列表页的动作按钮直接打开该形态并预选对应操作

**型号**

- **FR-026**: 录入页与详情页都必须提供型号选择器
- **FR-027**: 型号选择器只列出属于该资产类别及其祖先链、且未停用的型号
- **FR-028**: 录入时选择型号只填充尚未填写的字段；对已有资产更换型号时，必须逐键展示
  `当前值 → 新默认值` 并由操作者决定是否覆盖

**默认库存点**

- **FR-029**: 默认库存点必须可以在位置之间更换，但不得取消；取消请求必须返回明确错误而非静默成功
- **FR-030**: 当前作为默认库存点的位置不得被停用；必须先把标记转移到其他位置

**错误呈现**

- **FR-031**: 用户可见的错误信息中不得出现用于程序判定的英文标识文本

### Key Entities

- **唯一值记录**：某台资产在某个唯一信息项上曾经或正在持有的一个取值。带归档时间；
  未归档者参与唯一性约束，已归档者只参与搜索。取代 001 的「编号历史」实体
- **显示编号**：类别的一项设置，指向其有效字段集中的某个唯一信息项。不是一份数据，
  而是一个选择 —— 同一个表达式键可以在 A 类别当编号、在 B 类别当普通字段
- **静态键 / 表达式键**：信息项的两种形态。前者承载录入的内容，后者承载推导的结果。
  两者共用同一张表与同一套绑定机制
- **依赖闭包**：一个表达式键递归读取到的全部信息项 key 的集合。绑定门禁的判定对象

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员新建一个类别并录入第一台设备，全程不需要理解或配置编号规则
- **SC-002**: 任意一台设备在界面上都有一个可以念出来、可以逐字输入的指代方式（0 台设备无从指代）
- **SC-003**: 已知设备上任意一个唯一标识（编号、MAC、厂商序列号），从输入到看到详情不超过 10 秒，
  且不需要知道该标识属于哪个字段
- **SC-004**: 修正一个唯一信息项后，用它的旧值仍能定位到该设备（100% 命中）
- **SC-005**: 一处会导致「该类别所有资产无法保存」的配置错误，100% 在配置操作被提交的那一刻
  被拒绝，且拒绝理由直接指向要先修改的那一项
- **SC-006**: 给一台设备做一次交接，从打开它的详情页到完成，不超过三次点击且不离开该页面
- **SC-007**: 同一种流转操作在列表页与详情页的表单字段、校验与结果完全一致（0 处行为差异）
- **SC-008**: 型号的默认值在录入一台设备时被实际使用（此前为 0 次）
- **SC-009**: 任何一次被系统拒绝的操作，其提示中不包含英文的程序标识文本（0 处泄漏）
- **SC-010**: 绕过保存管线直接修改资产取值后，对帐命令能报出这处漂移（100% 检出）

## Assumptions

- 本规格的全部设计决策以 `docs/design-baseline-v2.md`（决策 25–40）为准；
  未被 v2 触及的部分继续以 `docs/design-baseline.md`（决策 1–24）为准；
  开发与质量约束以 `.specify/memory/constitution.md`（v1.1.0）为准
- 存量 demo 数据中已生成的编号**直接丢弃**，迁移后用 `nexus seed` 重建。
  本特性不提供把旧编号搬进新模型的迁移路径
- 唯一信息项的归档值**允许**被另一台设备重新占用。001 的「编号不可重用」规则不再适用 ——
  它在只有编号一种唯一值时成立，推广到所有唯一字段后会误伤真实场景
- 「写连接池为 1」从此是性能选择而非正确性前提。本特性不改变该设置，
  但章程中该条硬规则的理由需要相应更新
- 以下能力明确不在本特性范围内：把已有编号数据迁入新模型、类别解绑的 HTTP 端点与界面、
  唯一性作用域细分（当前仍是全局唯一）、显示编号的继承、表达式键的返回类型声明
