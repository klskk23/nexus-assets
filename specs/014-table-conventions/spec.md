# 014 · 表格页的统一：筛选、搜索、翻页与 dialog

**分支**：`014-table-conventions` ｜ **状态**：设计已定，待实现

## 缘起

九个页面画表格，九种样子。盘出来是这样：

| 页面 | 表格 | 筛选 | 搜索 | 翻页 | 点击行 |
|---|---|---|---|---|---|
| 资产 | 手写 | 五项 | ✓ | ✓ | **跳转到新页面** |
| 审计 | 手写 | 四项 | ✗ | ✓ | 弹 dialog |
| 字段 | CrudPage | 类别 | ✗ | ✓ | 弹 dialog |
| 类别 | 手写（树） | ✗ | ✗ | ✗ | 弹 dialog |
| 型号 / 状态 / 持有方 / 角色 | CrudPage | ✗ | ✗ | ✗ | 弹 dialog |
| 账号 | CrudPage | ✗ | ✗ | ✗ | **没有行点击** |

「点击行弹 dialog」其实已经是八分之七的现状，真正的例外只有资产；缺的是筛选、搜索、
翻页——它们只在资产和半个审计上存在。

## 决策

### 决策 89：资产详情是盖在列表上的 dialog，但仍然是一个地址

`/assets/:id` **保留为路由**，渲染成「资产列表 + 盖在上面的 dialog」。

保留地址不是为了整齐，是因为有三条现成的路径依赖它：**扫码枪**精确命中一台时
`navigate('/assets/<id>')`——这就是「扫一下就打开那台设备」的全部实现；**录入完成**
跳到新设备；审计里「只看这个对象」将来要能点开那台设备。做成纯状态 dialog 会把这三条
当场打断，也没有链接可以发给同事。

dialog 里装：属性表单（动态字段、型号、归还地点、保存）、常用动作、**最近 5 条流转**。

**全量历史在 `/assets/:id/history`**，整页，就是现在 `AssetDetail` 的时间线那半截。
最近几条能回答绝大多数追问；真要翻历史的人愿意多点一下，而把几十条流转塞进对话框会
让它变成一个盒子里的页面，滚动条套滚动条。

直接打开 `/assets/:id` 时（刷新、扫码、外部链接）背后铺**未筛选的第一页列表**——关掉
dialog 就自然落在列表上，不需要「返回」按钮，也不会关出一片空白。

### 决策 90：九个页面共享同一套工具条

搜索框、筛选栏、翻页条、地址栏同步，每页都有。

| 页面 | 搜索 | 筛选 |
|---|---|---|
| 资产 | 已有 | 已有五项 |
| 类别 | 名称、编码 | —（树） |
| 字段 | 键名、显示名 | 类别 + 类型 |
| 型号 | 名称、厂商 | 类别 |
| 状态 | 名称、键名 | — |
| 持有方 | 名称、备注 | 类型 + 是否默认库存点 |
| 账号 | 邮箱、姓名 | 角色 + 启用状态 |
| 角色 | 名称 | — |
| 审计 | 目标名称 | 已有四项 |

三条规则：

- **搜索框每页都有**，包括永远只有三五行的状态与角色。一个控件的噪音，换掉一条
  「看情况」的规则——翻页条消失是因为没有第二页，一眼就懂；搜索框消失没有对应的直觉。
- **翻页条只在超过一页时出现**，沿用资产列表已有的行为。
- **地址栏同步**：`q` / `page` / `limit` + 各页自己的筛选键（`category_id`、`status`…），
  `replace` 不 `push`（013 之后那一轮定的：筛选不是一个「去过的地方」）。

### 决策 91：类别页不翻页，搜索时从树切成平铺

树上放分页是自相矛盾：第 2 页可能以某个子类别开头，它的父在第 1 页，缩进就成了没有
出处的悬空。

搜索也一样——只显示命中的几行，父级不在了，「SDWAN 路由器」是谁下面的就看不出来。
所以**一搜索就不再缩进**，每行显示完整路径「网络设备 / SDWAN 路由器」；清空搜索恢复
成树。找东西的人要的是「它在哪」，一行把路径写全比缩进更直接。

### 决策 92：服务端分页，信封按需返回

`/categories`、`/models`、`/statuses`、`/holders`、`/users`、`/roles` 接受
`q` / `offset` / `limit`：

- **带了分页参数** → `{items, total, offset, limit}`（与 `/fields`、`/assets` 一致）；
- **没带** → 今天的数组，原样返回。

这是**加**行为，不是改行为，理由有两条：

1. **zenith-printer 的 NEXUS 数据源按数组解析 `/api/categories`**。改形状会让对面刷新
   数据源当场报 `NEXUS_BAD_SHAPE`，而且旧版 zenith 配新版 nexus 会一直坏到对面也升级。
2. 这些列表在系统里有**两种用法**：当表格（要一页）和当查表（录入的类别下拉、流转的
   持有方下拉、账号页的角色下拉——要全量）。分页会把选项截断。

规则一句话：**带分页参数就是要一页，不带就是要全部**，写进合约。

### 决策 93：账号能改的东西补齐

现状是 `Create` / `SetRole` / `Disable`，**没有重新启用**——`PATCH /users/:id` 只认
`{"disable": true}`，给 `false` 被静默忽略。手滑停错一个同事、或有人休完假回来，界面上
没有任何办法把他打开，只能去改数据库。

行点击打开账号编辑 dialog，里面：

- 邮箱只读，**姓名可改**；
- **角色可改**（013 的两条守卫不变：最后一个管理员不能降级、不能改自己的角色）；
- **停用 / 启用成对**；
- **重置密码**，仅本地账号——OIDC 账号没有密码，界面上禁用并说明。破坏性操作，走
  `ConfirmDialog` 并要求输入该账号的邮箱。

### 决策 94：重置密码当场吊销那个人的全部会话

`token_version` 从 001 起就带在 JWT 里，注释写着「carried but not yet checked」。这一轮
把它接上：中间件比对令牌里的 `tv` 与账号上的 `tv`，重置密码时 `tv + 1`，并调用
`Sessions.RevokeUser` 吊销刷新令牌。

不这么做的话，「重置密码」只是换了个哈希：那人手上的访问令牌 15 分钟内继续有效、刷新
令牌一直有效。而管理员用到这条路径，多半是因为**这个账号出事了**——15 分钟的窗口正好
落在最不该有窗口的时候。

### 决策 95：抽零件，不做一个带三个特例开关的万能组件

- `useListQuery`：`q` / 筛选 / `page` / `pageSize` 的状态、地址栏同步、改筛选回第一页；
- `ListToolbar`：一栏式工具条（搜索框 + 筛选插槽 + 右端三点菜单）；
- `Pager`：已有，加上「装得下就不画」。

`CrudPage` 内部用这三个，六个元数据页因此自动获得全部能力。资产、审计、类别保持各自的
表格（勾选列与底部操作栏、只读、树），但用同样的零件。

不把三个手写页塞进 `CrudPage`，是因为它得长出「没有新建按钮」「勾选列」「树形渲染」三个
特例开关，下次改它的人要先搞清楚自己在哪个分支里。CLAUDE.md 里已有的教训说的是同一件
事：「资产表格是手写的……007 定规范时就漏了它一次」——共享的部分只有一份，不同的部分
光明正大地不同。
