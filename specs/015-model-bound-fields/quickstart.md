# Phase 1 · 端到端走一遍

验收时按这个顺序走，每一步都对应 spec 的验收场景。假设已有类别「笔记本电脑」，
其下注册了戴尔与联想各一个型号。

## 1. 建一个型号模式字段

字段页 → 新建字段 → 键 `servicetag`、显示名 `ServiceTag`、类型 `text`、勾「唯一」。
绑定区把模式切到**型号**，勾选两个戴尔型号，保存。

**预期**：创建成功；字段列表里这一行显示它绑到了两个型号。

## 2. 互斥被守住

再建一个字段，先绑到「笔记本电脑」类别，保存；然后编辑它，尝试改绑型号。

**预期**：被拒绝，提示一个字段只能是纯类别或纯型号绑定
（`field_binding_mode_conflict`）。

## 3. 录入表单只对戴尔出现这个字段

资产页 → 录入设备 → 类别选「笔记本电脑」。

- 型号选戴尔 → **预期**：表单上出现 ServiceTag。
- 型号改选联想 → **预期**：ServiceTag 从表单上消失。
- 型号留空 → **预期**：ServiceTag 不出现。

## 4. 唯一性跨型号生效

在两个**不同的**戴尔型号下各录一台设备，ServiceTag 都填 `ABC1234`。

**预期**：第二台被拒绝，提示编号重复——范围是这个字段绑到的所有型号合起来
（决策 99），不是每个型号各自一个命名空间。

## 5. `display_key` 拒绝型号字段

类别页 → 编辑「笔记本电脑」→ 尝试把编号字段设为 ServiceTag。

**预期**：ServiceTag 不在候选里（或选中后被拒，
`display_key_not_category_field`）——决策 100。

## 6. 换型号后旧值进归档

拿第 3 步那台戴尔设备（ServiceTag 已填），把它的型号改成联想，保存。

**预期**：保存成功、不被阻断；ServiceTag 的值出现在「已归档字段」里，只读可查；
资产的活跃字段里不再有它。

## 7. 列表筛选与显示列解锁

资产页 → 类别筛到「笔记本电脑」。

- 未选型号时打开显示列下拉 → **预期**：ServiceTag 的勾选框**禁用**（不是隐藏），
  `title` 说明需要先选型号。
- 型号筛到戴尔 A 型号 → **预期**：绑在 A 上的 ServiceTag 可勾；
  绑在别的型号上的字段仍禁用。
- 勾上 ServiceTag → **预期**：表格出现该列，戴尔设备有值。
- 清空型号筛选 → **预期**：该列自动收回，不留「有表头无内容」的空列。
- 检查地址栏 → **预期**：型号筛选在 URL 里（`model_id=…`），
  刷新后仍在；关掉浏览器重开则为空（不做跨会话持久化）。

## 8. 弹窗顶部的属性卡

点开任意一台设备。

**预期**：弹窗最顶部（流转卡**之上**）有一张只读卡，列出这台设备全部动态字段
的名称与当前值；戴尔设备的卡里包含 ServiceTag。
卡里**没有**状态、当前持有方、负责人、备注——那四样仍在它们原来的位置。
下方的「编辑设备属性」折叠面板**照常存在且可用**。

## 9. 导入模板与错配拒绝

导入页 → 选「笔记本电脑」→ 下载模板。

**预期**：模板里有 ServiceTag 列。

填两行：一行 `model` 填戴尔、ServiceTag 有值；一行 `model` 填联想、ServiceTag 也有值。
上传预览。

**预期**：第二行被标为错误，说明该字段对所选型号不适用（`field_not_for_model`）；
预览不写入任何数据。

## 10. 导出列固定

资产页 → 类别筛到「笔记本电脑」→ 型号筛到**联想**（结果里没有任何戴尔设备）→ 导出。

**预期**：CSV 里**仍然有** ServiceTag 这一列，每行为空——列是 schema 的事，
行才是查询的事（决策 102）。

再勾选同类别下的戴尔与联想设备各一台 → 导出。

**预期**：得到**一个** CSV，不按型号分包。

## 11. 回归：既有行为不变

- `GET /api/categories` 仍返回**数组**（不带分页参数时），zenith 数据源不受影响。
- 导出的固定九列（编号/类别/状态/持有方/负责人/型号/厂商/备注/建档时间）位置不变。
- 类别模式字段的唯一性范围仍是类别子树。
- 型号上的 `attr_defaults`（选型号时复制默认值）行为不变。
